## Executive Summary

### Overall Health Assessment: 4 / 10

The core pipeline logic is feature-rich and demonstrates genuine architectural thinking (state-machine orchestration, structured output repair, multi-provider LLM transport, continue-run from artifacts). However, 24 iterative plan-and-implement cycles without refactoring have produced severe technical debt:

- **Security:** 8 CRITICAL/HIGH findings including command injection via LLM-controlled branch names, GitHub PAT written to `.git/config` and leaked via unauthenticated REST API, `NODE_TLS_REJECT_UNAUTHORIZED=0` process-wide, and shell tool executing agent-authored strings with full env inheritance.
- **Dead code:** ~146 unused exports, 94 unused locals (compiler-verified), 7 never-written state channels, 4 orphaned files (~600 LOC), and multiple features that appear implemented but are inert (run invariants 90% unreachable, layout-lint unwired, pause accounting unconnected).
- **Structure:** Two 2000+ line god files (`pr-workflow.ts`, `nodes.ts`), a 1026-line config with zero validation, near-zero test coverage on the highest-risk modules, and 15 global mutable singletons that corrupt under concurrent server runs.
- **Duplication:** ~2,500 LOC of mechanical duplication across the codebase (5 git-exec helpers, 4 file-walkers, 3 import-extractors, 3 HITL resume loops, 11 node preambles, 27 identical logger mocks in tests, 9 hand-copied state fixtures).
