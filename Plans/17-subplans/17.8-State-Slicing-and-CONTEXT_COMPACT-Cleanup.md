Five targeted state-slicing fixes that improve output quality rather than cost, plus removal of the dead `CONTEXT_COMPACT` flag and all its non-compact branches. ## Implementation Details

### Fix 1: Summarise epics for PM (nodes.ts ~line 858)

**Current:** PM gets `JSON.stringify(state.epics, null, 2)` at priority 1 (never clipped). This dumps the full epic structure.

**Change:** Add `summariseEpics(epics)` that produces a compact one-line-per-epic format:
```
- EPIC-001: title — one-sentence description
- EPIC-002: title — one-sentence description
```

Find where this is used in nodes.ts and replace `JSON.stringify(state.epics, null, 2)` with `summariseEpics(state.epics)`.

If `summariseEpics` doesn't exist yet, add it to the context-builder module (likely `src/conductor/context-builder.ts` or similar — search for where `summariseFileChanges` is defined and add it there).

### Fix 2: QA lead gets acceptance criteria (nodes.ts ~line 1234)

**Current:** The QA-lead section is titled `Test Plan` but passes `state.testPlan`, which is **always empty at that point** — the QA lead is the agent that *creates* it. This means the QA lead currently receives **no acceptance criteria at all**, which is a real quality bug (shows up as `AC coverage: 0/54 verified` in Pacman4).

**Change:** Replace with:
```ts
{
    title: 'User Stories with Acceptance Criteria',
    body: storiesForIds(state.userStories, state.userStories.map(s => s.id)),
    priority: 1,
}
```

This gives the QA lead the actual acceptance criteria it needs to write meaningful test plans.

Find the exact location by searching for the QA-lead context assembly in nodes.ts (look for `testPlan` or `Test Plan` in the context sections).

### Fix 3: DevOps non-compact branch (nodes.ts ~line 1558)

**Current:** DevOps non-compact branch dumps the entire `state.fileChanges`.

**Change:** The compact branch is fine. The non-compact branch will be deleted as part of Fix 5 below.

### Fix 4: Lower dev agent file-changes limit (nodes.ts ~line 1123)

**Current:** `Files Already Written` for dev agents is priority 3 and capped at 60 files.

**Change:**
- Lower `DEV_CONTEXT_FILE_CHANGES_LIMIT` (or the inline constant) from `60` to `25`
- Change `summariseFileChanges` to group by directory rather than listing individual paths:
  ```
  src/components/ (8 files), src/utils/ (3 files), tests/ (5 files)
  ```
  instead of listing all 25 individual file paths.

Find `summariseFileChanges` (likely in context-builder.ts) and modify it to group by directory when the count is high.

### Fix 5: Delete all `CONTEXT_COMPACT` branches

**Scope:** Every `if (CONTEXT_COMPACT) … else …` branch in:
- `src/conductor/nodes.ts` (search for `CONTEXT_COMPACT` — expect ~5 occurrences)
- `src/conductor/pr-workflow.ts` (search for `CONTEXT_COMPACT` — expect 1-2 occurrences)

**Action:** Keep only the `CONTEXT_COMPACT=true` branch (the compact code). Delete:
- The `if` / `else` wrapper (just keep the compact body)
- The non-compact `else` branch entirely
- All imports of `CONTEXT_COMPACT` from these files

**Also:**
- Remove `export const CONTEXT_COMPACT` from `src/config.ts`
- Remove the `CONTEXT_COMPACT` line from `.env.example`

**Search strategy:** Run a global grep for `CONTEXT_COMPACT` to find ALL references. Every reference must be addressed:
- In `config.ts`: delete the export
- In `.env.example`: delete the documentation line
- In `nodes.ts`: keep the compact branch, delete the conditional and non-compact branch
- In `pr-workflow.ts`: same as above
- In any test files: remove or update references

### Update `tests/context-builder.test.ts`

Add tests for:
- **`summariseEpics`:** Given a list of epics with ids, titles, and descriptions, produces the compact one-line format
- **Regrouped `summariseFileChanges`:** Given 30 file changes across 5 directories, produces the grouped format (`src/components/ (8 files)`)
- **File changes limit:** With `limit=25`, only 25 entries (or groups) are shown

## Risks

- **Removing CONTEXT_COMPACT could break something if it was used elsewhere.** Mitigated by the grep check — every reference must be found and addressed.
- **QA lead fix changes what the agent sees.** This is intentional — the current state is a bug (QA lead receives no acceptance criteria). The fix improves quality.
- **File-changes grouping loses individual file visibility.** Agents can still use `list_dir` or `search_code` to find specific files. The grouped format gives them directory-level awareness with much less token cost.

- This sub-plan's savings are <1% of tokens, but the quality improvements (especially Fix 2) make it worth doing.
