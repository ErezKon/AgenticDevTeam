# Sub-plan 17.6: Agent Respawn System

**Parent plan:** `Plans/17.Token reduction plan - Opus 5 Medium.md` — Step 8  
**Complexity:** High  
**Prerequisites:** Sub-plan 17.1 (needs `AGENT_RESPAWN_ENABLED`, `AGENT_RESPAWN_MAX_GENERATIONS`, `AGENT_RESPAWN_TOKEN_THRESHOLD` config flags)  
**Expected token saving:** ~10-15%, plus structural fix for context rot

---

## Objective

Replace the "poison and flail" pattern with "summarise and respawn." Today, hitting the tool-call ceiling produces 114 `poisoning all tools` events — the agent keeps being invoked with a *maximal* history while every tool returns an error string. That is the most expensive possible state.

Instead: bound each invocation's context to O(threshold), build a deterministic handoff summary from the message history (no extra LLM call), and respawn the agent with a fresh `MemorySaver` and clean context. Generation 2 starts at ~4k input tokens with *better* signal than generation 1 had at 15k.

## Implementation Details

### 1. Create `src/conductor/agent-respawn.ts`

```ts
import { AIMessage, ToolMessage, type BaseMessage } from '@langchain/core/messages';

export interface HandoffSummary {
    generation: number;
    filesWritten: { path: string; action: string }[];
    commandsRun: { command: string; exitCode: number }[];
    keyFindings: string[];
    remainingWork: string;
}

/**
 * Build a compact handoff brief from a completed (or ceiling-terminated)
 * agent invocation. Derived DETERMINISTICALLY from the message history -
 * no extra LLM call, so the summary itself is free.
 */
export function buildHandoff(messages: BaseMessage[], generation: number): HandoffSummary;

/** Render a HandoffSummary as the prompt section for the successor agent. */
export function renderHandoff(h: HandoffSummary): string;
```

**`buildHandoff` implementation:**

Walk all `AIMessage`s with `tool_calls` and their corresponding `ToolMessage` results:

1. **`filesWritten`:** Look for `tool_calls` with `name: 'write_file'` or `name: 'edit_file'`:
   - Extract `filePath` (or `path`) from `args`
   - Set `action` to `'created'` for `write_file`, `'edited'` for `edit_file`
   - **Never include file content** — only path and action
   - Deduplicate by path (keep the last action)

2. **`commandsRun`:** Look for `tool_calls` with `name: 'run_command'`:
   - Extract `command` from `args`
   - Parse exit code from the corresponding `ToolMessage` result's first line (look for patterns like `Exit code: N` or `exit code N`)
   - If exit code can't be parsed, default to `0`

3. **`keyFindings`:** Take the agent's last non-empty text content (from `AIMessage.content` where content is a string and non-empty), clipped to 800 chars.

4. **`remainingWork`:** Set to a generic message like `'Continue implementing the remaining stories and fix any failing tests.'` — this is a deterministic fallback since we can't ask the LLM.

**`renderHandoff` implementation:**

Produce a structured prompt section:

```
## Previous Attempt (generation ${h.generation}) — you are continuing this work
Files already written: ${h.filesWritten.map(f => `${f.path} (${f.action})`).join(', ')}
Commands run: ${h.commandsRun.map(c => `\`${c.command}\` (exit ${c.exitCode})`).join(', ')}
Findings: ${h.keyFindings.join(' ')}
Remaining: ${h.remainingWork}
Do NOT re-read files you already wrote unless you need to change them.
```

The output should be under 1,200 chars for a typical 30-tool-call history.

### 3. Modify `src/conductor/pr-workflow.ts` — Respawn loop

Find `invokeDevAgent` (around lines 226-262). Wrap it in a generation loop:

```ts
import { AGENT_RESPAWN_ENABLED, AGENT_RESPAWN_MAX_GENERATIONS } from '../config';
import { buildHandoff, renderHandoff, HandoffSummary } from './agent-respawn';

// Inside the dev agent invocation section:
let handoff: HandoffSummary | undefined;

for (let gen = 0; gen <= AGENT_RESPAWN_MAX_GENERATIONS; gen++) {
    // Build a fresh agent for each generation (fresh MemorySaver + thread_id)
    const { agent, isCeilingReached } = buildDevAgentFn(); // fresh agent
    
    const message = gen === 0
        ? baseMessage
        : [baseMessage, renderHandoff(handoff!)].join('\n');
    
    const threadId = `${baseThreadId}-gen${gen}-${Date.now()}`;
    const result = await agent.invoke(
        { messages: [{ role: 'user', content: message }] },
        { configurable: { thread_id: threadId } },
    );

    // If ceiling not reached, or respawn disabled, or max generations hit → return
    if (!AGENT_RESPAWN_ENABLED || !isCeilingReached() || gen === AGENT_RESPAWN_MAX_GENERATIONS) {
        return parseResult(result);
    }

    // Build handoff for next generation
    handoff = buildHandoff(result.messages, gen + 1);
    log.info(`Respawning ${agentId} (generation ${gen + 1}): ` +
             `${handoff.filesWritten.length} files carried forward`);
    emitRunEvent('agent:respawn', { agentId, generation: gen + 1, files: handoff.filesWritten.length });
}
```

**Key points:**
- Each generation gets a fresh `MemorySaver` (because `buildDevAgent` allocates a new one)
- Each generation gets a fresh `thread_id`
- The handoff is deterministic — no extra LLM call
- `emitRunEvent('agent:respawn', ...)` emits the new event type (see below)
- When respawn is disabled (`AGENT_RESPAWN_ENABLED=false`), the loop runs only once and falls through to the existing poison-and-return behaviour

## Risks

- **Respawn with incomplete work:** The handoff summary carries file paths and commands, giving the successor agent enough context to continue. Files are already on disk in the worktree, so the successor can read them if needed.
- **Lower quality from fresh context:** The handoff is front-loaded and purpose-built — generation 2 starts with better signal than generation 1 had at 15k tokens. If quality drops, raise `AGENT_RESPAWN_MAX_GENERATIONS` or increase `AGENT_RESPAWN_TOKEN_THRESHOLD`.
- **Ordering dependency:** Sub-plan 17.7 (lower ceilings) MUST land AFTER this sub-plan. Lower ceilings without respawn would just mean more poisoned agents.

## Notes

- 114 `poisoning all tools` events were observed in Pacman4. Each one means the agent is being invoked with maximal history while every tool returns an error — the most expensive possible state.
- The deterministic handoff extraction is deliberate: an LLM-generated summary would cost a full-history LLM call, which is precisely what we are trying to avoid.
