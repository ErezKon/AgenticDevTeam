## Implementation Details

### 1. Modify `src/utils/token-tracker.ts`

**a) Add `invocationId` to `TokenCallRecord`:**

Find the `TokenCallRecord` type/interface and add:
```ts
invocationId?: string;
```

**b) Add invocation lifecycle methods to `TokenTracker` class:**

```ts
/** Start tracking a new agent invocation. Returns the invocation ID. */
startInvocation(agentId: string, phase: string): string {
    const id = `${agentId}-${phase}-${Date.now()}`;
    this._currentInvocationId = id;
    return id;
}

/** End the current invocation tracking. */
endInvocation(id: string): void {
    if (this._currentInvocationId === id) {
        this._currentInvocationId = undefined;
    }
}
```

Add a private `_currentInvocationId?: string` field to the class.

**c) Thread `invocationId` through `recordCall`:**

In the `recordCall` method, if `_currentInvocationId` is set, include it in the `TokenCallRecord`:
```ts
recordCall(record: Omit<TokenCallRecord, 'invocationId'>): void {
    this._records.push({
        ...record,
        invocationId: this._currentInvocationId,
    });
}
```

**Note:** The `TokenUsageCallbackHandler` already creates per-agent instances, so `_currentInvocationId` is set as a mutable field on the tracker. Check how `TokenUsageCallbackHandler` interacts with `tokenTracker` — it likely calls `recordCall` directly. The invocation ID should be set by `startInvocation` before the agent is invoked and cleared by `endInvocation` after.

### 2. Modify `src/utils/token-report.ts`

**Add an Invocation Efficiency table** to both the HTML report and the `generateTokenReport` / `refreshTokenReport` flow.

The table schema:

| Column | Source |
|---|---|
| agent | The agent ID (e.g. `principal-frontend`) |
| invocations | Count of unique `invocationId` values for this agent |
| avg calls/invocation | Total calls for agent ÷ invocations |
| avg input/call | Average input tokens per call |
| first-call input | Input tokens on the first call of the invocation |
| last-call input | Input tokens on the last call |
| growth factor | last-call input ÷ first-call input |
| respawns | Count of `agent:respawn` events for this agent (from event bus or a counter) |

**Growth factor** is the direct read-out of ReAct replay cost:
- Pre-change baseline (Pacman4): roughly 4.5x for `senior-frontend`
- Post-change target (after Steps 2-3): under 2.0x

**Implementation:**

Add a function like `buildInvocationEfficiencyTable(records: TokenCallRecord[])` that:
1. Groups records by `invocationId`
2. For each invocation group, finds first and last call input tokens
3. Computes growth factor
4. Aggregates by agent
5. Returns the table data

In the HTML report generator, add a new section after the existing tables with this Invocation Efficiency table. Style it consistently with the existing dark-theme Chart.js report.

In the finalize summary (the text output), add the table in a simple text format.

  Increment in `truncateToolResult` when truncation actually occurs.
