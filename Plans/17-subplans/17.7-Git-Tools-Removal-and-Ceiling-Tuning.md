# Sub-plan 17.7: Git Tools Removal & Ceiling Tuning

**Parent plan:** `Plans/17.Token reduction plan - Opus 5 Medium.md` — Step 7  
**Complexity:** Low  
**Prerequisites:** Sub-plan 17.1 (needs `DEV_GIT_TOOLS_ENABLED` flag), Sub-plan 17.6 (respawn must be in place BEFORE lowering ceilings — otherwise lower ceilings just mean more poisoned agents)  
**Expected token saving:** ~8-12% (removing a tool call at position N removes not just that call but the replay of everything before it)

---

## Objective

Remove git tools from dev agents (the PR workflow already commits/pushes for them) and lower the tool-call ceilings now that history compaction and respawn are in place. This eliminates ~8 tool schemas from every dev request and reduces the maximum history size at ceiling.

## Implementation Details

### 1. Modify `src/agents/developers/dev-agent.builder.ts`

**a) Conditionally include git tools:**

Find the tool array construction (around line 50-60 where tools are assembled). Currently it includes `createGitTools(workspaceRoot, gitContext, baseBranch)` unconditionally.

Change to:
```ts
import { DEV_GIT_TOOLS_ENABLED } from '../../config';

const tools = [
    ...createWorkspaceTools(workspaceRoot),
    createShellTool(workspaceRoot),
    ...(DEV_GIT_TOOLS_ENABLED ? createGitTools(workspaceRoot, gitContext, baseBranch) : []),
];
```

This removes ~8 tool schemas (git_checkout_branch, git_switch_branch, git_add, git_commit, git_push, git_status, git_diff, git_current_branch, git_merge_base_diff, git_diff_file, git_diff_stat, git_log) from **every** dev request when `DEV_GIT_TOOLS_ENABLED=false` (the default).

The `run_command` tool still allows git commands if an agent genuinely needs them, and the shell denylist already blocks force-push.

**b) Lower the maxToolCalls ceilings:**

Find where maxToolCalls per rank are set (around lines 59-61):

Current values:
| Rank | maxToolCalls now |
|---|---|
| principal | 40 |
| senior | 35 |
| junior | 30 |

New values:
| Rank | maxToolCalls proposed |
|---|---|
| principal | 26 |
| senior | 22 |
| junior | 18 |

Update the ceiling assignments accordingly. The ceremony calls (git add, commit, push, convention reads) are gone, and history is now compacted, so agents accomplish the same work in fewer calls.

### 2. Modify `src/config.ts` — Lower `DEV_RECURSION_LIMIT`

Find `DEV_RECURSION_LIMIT` (line 127-128):
```ts
export const DEV_RECURSION_LIMIT =
    parseInt(process.env.DEV_RECURSION_LIMIT ?? process.env.AGENT_RECURSION_LIMIT ?? '84', 10);
```

Change the default from `'84'` to `'58'`:
```ts
export const DEV_RECURSION_LIMIT =
    parseInt(process.env.DEV_RECURSION_LIMIT ?? process.env.AGENT_RECURSION_LIMIT ?? '58', 10);
```

This maintains the documented invariant: `recursionLimit >= maxToolCalls*2 + headroom` → `58 >= 26*2 + 6`.

Also update the comment above it (around lines 107-122) to reflect the new ceilings:
```ts
/**
 * ...
 * The dev limit must be >= (maxToolCalls × 2) + headroom. The loop guard's
 * maxToolCalls per rank are: principal 26, senior 22, junior 18. At 58
 * (26 × 2 + 6 headroom), the recursion limit no longer fires before the
 * loop guard for any rank.
 * ...
 */
```

Check if any tests assert specific default ceiling values (40, 35, 30) or `DEV_RECURSION_LIMIT=84`. If so, update them to the new values (26, 22, 18, and 58 respectively).

## Risks

- **Removing git tools changes dev behaviour:** The PR workflow already commits and pushes, so this should be a no-op. `DEV_GIT_TOOLS_ENABLED=true` restores the old surface instantly.
- **Lower ceilings could truncate legitimate work:** This is exactly what respawn (Sub-plan 17.6) is for — hitting the ceiling now continues with clean context instead of aborting. If quality drops, raise ceilings *and* keep respawn.
- **Must land AFTER respawn:** If this lands before Sub-plan 17.6, lower ceilings would just produce more poisoned agents with no recovery path.

---

## Notes

- This sub-plan is intentionally small. The git tools removal is a one-line conditional, and the ceiling changes are number updates.
- The `run_command` tool is NOT removed, so agents can still run `git log` or `git status` through the shell if absolutely needed.
- The shell denylist (`isDeniedCommand`) already blocks `git push --force` and similar dangerous commands.
