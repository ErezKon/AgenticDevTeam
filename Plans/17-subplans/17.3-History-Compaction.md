# Sub-plan 17.3: History Compaction (preModelHook)

**Parent plan:** `Plans/17.Token reduction plan - Opus 5 Medium.md` — Step 3  
**Complexity:** High  
**Prerequisites:** Sub-plan 17.1 (needs `HISTORY_COMPACTION_ENABLED`, `HISTORY_KEEP_RECENT_TOOL_RESULTS`, `HISTORY_MAX_CHARS`, `MAX_TOOL_RESULT_CHARS` config flags)  
**Expected token saving:** ~25-35% of total input tokens — the single biggest lever

---

## Objective

Implement a `preModelHook` that compacts the ReAct message history before each LLM call. This directly fixes the O(steps^2) input-cost growth and the lost-in-the-middle problem. The hook replaces *only* the messages sent to the LLM — the durable `messages` state in LangGraph's `MemorySaver` is untouched.

The key insight: `createReactAgent` from `@langchain/langgraph@1.0.7` supports `preModelHook`, which returns `{ llmInputMessages }` — a replacement message list used only for the LLM call. This is confirmed in `node_modules/@langchain/langgraph/dist/prebuilt/react_agent_executor.js` around lines 143 and 220.

## Implementation Details

### 1. Create `src/agents/_shared/history-compactor.ts`

```ts
import { AIMessage, ToolMessage, type BaseMessage } from '@langchain/core/messages';
import {
    HISTORY_KEEP_RECENT_TOOL_RESULTS, HISTORY_MAX_CHARS, MAX_TOOL_RESULT_CHARS,
} from '../../config';

export interface CompactionStats {
    originalChars: number;
    compactedChars: number;
    toolResultsStubbed: number;
    writeArgsStubbed: number;
}

/**
 * Compact a ReAct message history for the next LLM call.
 *
 * Rules, in order:
 *  1. Never touch the first message (the task) or the last `keepRecent`
 *     tool results — the model needs both to make its next decision.
 *  2. Replace the CONTENT of older ToolMessages with a one-line receipt:
 *     `[read_file src/App.tsx -> 4,210 chars, elided]`.
 *  3. Replace the `content` / `newString` ARGUMENTS of older write_file /
 *     edit_file tool calls with `[<n> chars elided - file already written]`.
 *     The tool NAME and PATH stay, so the model still knows what it did.
 *  4. If still over `HISTORY_MAX_CHARS`, drop the oldest stubbed pairs
 *     (never the first message, never the last `keepRecent`).
 *
 * Pure function - no I/O, no LangGraph types beyond BaseMessage.
 */
export function compactHistory(
    messages: BaseMessage[],
    opts?: { keepRecent?: number; maxChars?: number },
): { messages: BaseMessage[]; stats: CompactionStats } { /* implementation below */ }
```

**Implementation guidance for the developer:**

1. **Measure `originalChars`:** Sum all `JSON.stringify(m.content).length` + `JSON.stringify(m.tool_calls ?? []).length` for all messages.

2. **Identify the "recent" window:** Walk backwards from the end of the array, counting `ToolMessage` instances. Once `keepRecent` (default: `HISTORY_KEEP_RECENT_TOOL_RESULTS`, typically 3) `ToolMessage`s have been counted, mark that index as the boundary. Everything from index 1 (skipping message 0 = the task) to the boundary is eligible for stubbing.

3. **Stub ToolMessages (rule 2):** For each eligible `ToolMessage`:
   - Extract the tool name from `m.name`
   - Measure the original content length
   - Construct a **new** `ToolMessage` (never mutate in place — `messages` is durable state):
     ```ts
     new ToolMessage({
         content: `[${m.name} -> ${originalLen.toLocaleString()} chars, elided]`,
         tool_call_id: m.tool_call_id,
         name: m.name,
     })
     ```
   - Increment `stats.toolResultsStubbed`

4. **Stub AIMessage tool-call args (rule 3):** For each eligible `AIMessage` that has `tool_calls`:
   - Clone: `new AIMessage({ content: m.content, tool_calls: m.tool_calls!.map(tc => ({ ...tc, args: elideBigArgs(tc.args) })), id: m.id })`
   - `elideBigArgs(args)` replaces any string arg value longer than 400 chars with `[${len} chars elided]`. Specifically target `content` and `newString` args (from `write_file` / `edit_file`), but apply to any string arg over 400 chars.
   - **CRITICAL invariant:** An `AIMessage` with `tool_calls` MUST always be followed by its matching `ToolMessage`s or LLM providers will reject the request. Stub, never delete, unless you drop the whole AI/Tool group together in rule 4.
   - Increment `stats.writeArgsStubbed` for each arg elided

5. **Hard ceiling enforcement (rule 4):** If after stubbing the total chars still exceeds `maxChars` (default: `HISTORY_MAX_CHARS`):
   - Drop the oldest stubbed AI+Tool message groups (starting from index 1, never touching index 0 or the recent window)
   - When dropping an `AIMessage` with `tool_calls`, you MUST also drop all its matching `ToolMessage`s (match by `tool_call_id`)
   - Keep dropping groups until under budget or only protected messages remain

6. **Return:** `{ messages: newMessages, stats }` where `stats.compactedChars` is the re-measured total.

### 2. Modify `src/agents/_shared/agent-factory.ts`

The current `buildAgent` function (line 48) creates a `createReactAgent` call around line ~110-121. Modify it to:

Add imports:
```ts
import { RunnableLambda } from '@langchain/core/runnables';
import { compactHistory } from './history-compactor';
import { HISTORY_COMPACTION_ENABLED } from '../../config';
```

Before the `createReactAgent` call, add:
```ts
const preModelHook = HISTORY_COMPACTION_ENABLED
    ? RunnableLambda.from((state: { messages: BaseMessage[] }) => {
        const { messages: compacted, stats } = compactHistory(state.messages);
        if (stats.originalChars !== stats.compactedChars) {
            factoryLog.debug(
                `${cfg.id}: history ${stats.originalChars} -> ${stats.compactedChars} chars ` +
                `(${stats.toolResultsStubbed} results, ${stats.writeArgsStubbed} write args stubbed)`,
            );
        }
        return { llmInputMessages: compacted };
    })
    : undefined;
```

Then pass `preModelHook` to `createReactAgent`:
```ts
return createReactAgent({ llm: model, checkpointer, prompt, tools: guardedTools, preModelHook });
```

Look at the existing `createReactAgent` call in `agent-factory.ts` and add `preModelHook` to its options object. The `createReactAgent` function accepts it as a top-level option.

### 3. Create `tests/history-compactor.test.ts`

Test cases (all critical):

1. **History under budget is returned unchanged:** Create a short message array (system + 2 tool calls). Verify the returned messages have identical content (referentially or deep-equal).

2. **First message is never altered:** Create a long history. Verify `result.messages[0]` has identical content to the input's first message.

3. **Last N tool results are never altered:** Create a history with 10 ToolMessages. With `keepRecent=3`, verify the last 3 ToolMessages have identical content to the originals.

4. **Old read_file result is stubbed:** Create a `ToolMessage` with `name: 'read_file'` and 20,000 chars of content at an early position. Verify it's replaced by a stub under 120 chars containing `elided`.

5. **write_file tool call args are elided:** Create an `AIMessage` with `tool_calls: [{ name: 'write_file', args: { filePath: 'src/foo.ts', content: 'x'.repeat(5000) }, id: 'tc1' }]`. Verify the output `AIMessage` keeps `filePath` but `content` is replaced with an elision marker.

6. **AIMessage/ToolMessage pairing invariant:** After compaction, for every `AIMessage` with `tool_calls`, verify each `tool_call_id` has a matching `ToolMessage` in the output. This is the provider-validity invariant — if violated, the LLM API will reject the request.

7. **Hard ceiling drops oldest groups:** Create a history that exceeds `HISTORY_MAX_CHARS` even after stubbing. Verify groups are dropped from the oldest end, and the result is under the ceiling.

8. **Stats are accurate:** Verify `originalChars > compactedChars` and `toolResultsStubbed` counts match expectations.

**Test helpers:** Create factory functions like `makeToolMsg(name, content, toolCallId)` and `makeAIMsg(content, toolCalls?)` to keep tests readable.

## Key Invariants (MUST be maintained)

1. **Message 0 (task prompt) is NEVER modified or dropped**
2. **Last N ToolMessages are NEVER modified** (the model needs recent context for its next decision)
3. **Every AIMessage.tool_calls[i].id has a matching ToolMessage** in the output array
4. **No in-place mutation** of input messages — always construct new message objects
5. **The durable MemorySaver state is unaffected** — `preModelHook` only changes what the LLM sees

## Risks

- **Provider rejects malformed message sequence:** The strictest constraint — every `AIMessage.tool_calls[i].id` must have a matching `ToolMessage`. This is enforced as a unit test invariant and by never deleting a ToolMessage without its parent AIMessage.
- **`preModelHook` + `MemorySaver` interaction:** `llmInputMessages` is consumed for the LLM call only; durable `messages` state is untouched. `extractTokenUsageFromMessages` and last-message JSON parsing operate on the durable state, so they are unaffected.
- **Compaction hides something the model needed:** Mitigated by always keeping the last 3 tool results verbatim, by stubs that name the file and its size so the model can re-read deliberately, and by `HISTORY_COMPACTION_ENABLED=false` as an instant revert.
