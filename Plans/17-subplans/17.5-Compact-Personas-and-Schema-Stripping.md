# Sub-plan 17.5: Compact Personas & Schema Stripping

**Parent plan:** `Plans/17.Token reduction plan - Opus 5 Medium.md` — Step 5  
**Complexity:** High  
**Prerequisites:** Sub-plan 17.1 (needs `PERSONA_COMPACT` config flag)  
**Expected token saving:** ~10-15% of total input tokens (this text is billed on all ~3,400 calls)

---

## Objective

Shrink the fixed per-call preamble that is re-sent on every LLM call. The first dev call shows `in=3995` for `out=85` — that's ~4,000 tokens of system persona, injected JSON schema, 11 tool schemas, and the task message. Multiplied by 3,406 calls, this is ~13.6M tokens (44% of all input) of the same text re-sent. This sub-plan targets the persona and schema portions.

## Implementation Details

### 1. Modify `src/agents/_shared/persona.ts`

**Current structure (222 lines):**
- `buildDevPersona(cfg: DevPersonaConfig)` — builds ~7,000 char system prompt with sections: `<critical_rules>`, `<tdd_rules>`, `<workflow>`, `<git_workflow>`, `<maintain_mode>`, `<output_rules>`, `<tool_usage>`
- `buildReviewerPersona(cfg)` — reviewer prompt with `<tool_usage>` section

**Changes:**

a) **Add `buildDevPersonaCompact(cfg: DevPersonaConfig & { isMaintainMode?: boolean })`** that produces a ~2,500 char persona (down from ~7,000):

- **Delete `<git_workflow>` entirely** (lines ~117-134, ~1,100 chars). The PR workflow already runs `git add .`, commits and pushes after the dev agent returns (`pr-workflow.ts:511-516`) and after every fix (`987-992`). Replace with one line:
  ```
  Do not run git commands - the conductor commits and pushes your work.
  ```
  This also removes 5-10 wasted tool calls per invocation.

- **Delete `<maintain_mode>` from the base persona** (lines ~136-146, ~950 chars). Append it ONLY when `isMaintainMode` is true. The `isMaintainMode` flag is threaded from `developmentNode` (see below).

- **Merge `<tdd_rules>` into `<workflow>`** — the two blocks restate the same instruction six times. Keep three lines:
  ```
  Write a failing test BEFORE implementing. Run tests after every change. Never commit if tests fail.
  ```

- **Compress `<critical_rules>`** from 10 multi-line bullets to 6 single-line bullets, preserving the semantics of:
  1. Stay in scope — only implement your assigned stories
  2. Match the tech stack specified in the architecture
  3. Keep the app runnable at all times
  4. No dead code — every function, import, and variable must be used
  5. Tests must pass before you finish
  6. Every test file must have at least one `it()` block

- **Drop `<output_rules>`** entirely — the injected JSON schema already specifies `fileChanges` / `notes` / `mermaidDiagram`. The model knows the structure from the schema.

- **Add to the compact persona:** `Batch your work: write a complete file in one write_file call rather than many edit_file calls.` (Pacman4 shows repeated `edit_file` on the same file triggering the loop guard.)

b) **Modify `buildDevPersona`** to delegate:
```ts
import { PERSONA_COMPACT } from '../../config';

export function buildDevPersona(cfg: DevPersonaConfig & { isMaintainMode?: boolean }): string {
    if (PERSONA_COMPACT) return buildDevPersonaCompact(cfg);
    return /* existing full persona */;
}
```

c) **Shrink `buildReviewerPersona`:** Compress `<tool_usage>` from 9 lines to 3:
```
Use git_merge_base_diff to see changes, read_file for specific files, and search_code to check patterns. Do not modify any files.
```

### 2. Modify `src/agents/_shared/agent-factory.ts` — Schema stripping

Currently `stripDeepDescriptions` (around line 112) strips `description` only at `depth > 2`.

Add a stricter mode gated by a check (can be a simple constant since schema stripping has no runtime cost concern):

```ts
/**
 * Strip all descriptions from the response schema to reduce per-call token cost.
 * Field names in DeveloperOutputSchema (fileChanges, notes, mermaidDiagram, etc.)
 * are self-documenting, so descriptions add tokens without value.
 */
function stripAllDescriptions(schema: Record<string, unknown>): Record<string, unknown> {
    // Deep clone and remove:
    // - All 'description' keys at every level
    // - All 'additionalProperties' keys  
    // - All '$schema' keys
    // - All empty 'required: []' arrays
    // Return the stripped schema
}
```

Modify the existing schema injection logic to use `stripAllDescriptions` instead of `stripDeepDescriptions`. The old function can remain for reference but should not be called.

### 3. Thread `isMaintainMode` through the call chain

The maintain-mode flag needs to flow from the development node to the dev agent builder:

**`src/conductor/nodes.ts`** — in `developmentNode` or wherever `dispatchDevelopers` is called:
- `state.codebaseAnalysis != null` indicates maintain mode (existing codebase was analyzed)
- Pass `isMaintainMode: state.codebaseAnalysis != null` to `dispatchDevelopers`

**`src/agents/developers/dispatcher.ts`** — `dispatchDevelopers`:
- Accept `isMaintainMode` in its parameters/options
- Pass it through to `executePRWorkflow` calls

**`src/conductor/pr-workflow.ts`** — `executePRWorkflow`:
- Accept `isMaintainMode` in `PRWorkflowInput` type
- Pass it through to `buildDevAgent` calls

**`src/agents/developers/dev-agent.builder.ts`** — `buildDevAgent`:
- Accept `isMaintainMode?: boolean` parameter
- Pass it to `buildDevPersona({ ...cfg, isMaintainMode })`

### 4. Create `tests/persona.test.ts`

Test cases:
- **Compact persona is under 3,000 chars:** `buildDevPersonaCompact(sampleConfig).length < 3000`
- **Contains load-bearing phrases:** Output contains `NO DEAD CODE` (or equivalent), `at least one` (for test blocks), tech-stack fidelity rule
- **Does NOT contain git workflow in compact mode:** Output does NOT contain `git add`, `git commit`, `git push`
- **Contains maintain-mode section ONLY when isMaintainMode=true:**
  - `buildDevPersonaCompact({ ...cfg, isMaintainMode: false })` does NOT contain maintain-mode text
  - `buildDevPersonaCompact({ ...cfg, isMaintainMode: true })` DOES contain maintain-mode text
- **Compact persona mentions batching:** Contains `write a complete file in one write_file call` or similar
- **Full persona still works when PERSONA_COMPACT=false** (test both paths)
- **Reviewer persona is shorter:** `buildReviewerPersona(cfg).length` is less than before (or under a threshold)

## Risks

- **Compact persona might lose critical instructions:** Mitigated by unit tests that check for load-bearing phrases. The full persona is still available via `PERSONA_COMPACT=false`.
- **`isMaintainMode` threading touches many files:** Each file only gets a small change (adding a parameter and passing it through), so the risk is low. The chain is: nodes.ts → dispatcher.ts → pr-workflow.ts → dev-agent.builder.ts → persona.ts.
- **Schema stripping too aggressive:** The `DeveloperOutputSchema` field names (`fileChanges`, `filePath`, `content`, `notes`, `mermaidDiagram`) are self-documenting. If a model struggles, `PERSONA_COMPACT=false` reverts to the old behaviour which includes descriptions.

## Notes

- The 44% of input tokens that is the "same text re-sent" is the primary target. Even a 40% reduction in persona size saves ~5.4M tokens on a Pacman4-equivalent run.
- The `Batch your work` instruction addresses a specific observed pattern: Pacman4 shows repeated `edit_file` calls on the same file triggering the loop guard. One `write_file` replaces 3-5 `edit_file` calls.
