# Sub-plan 17.2: Tool Result Truncation

**Parent plan:** `Plans/17.Token reduction plan - Opus 5 Medium.md` — Step 2  
**Complexity:** Medium  
**Prerequisites:** Sub-plan 17.1 (config flags must exist, specifically `MAX_TOOL_RESULT_CHARS`)  
**Expected token saving:** ~15-20% of total input tokens

---

## Objective

Cap tool results at the source so that large file reads, shell output, and git diffs don't bloat the ReAct history. A capped result is cheaper on the step it appears AND on every subsequent replay. Create a shared truncation utility and apply it to all tool result sites.

## Implementation Details

### 1. Create `src/tools/_shared/truncate.ts`

```ts
import { MAX_TOOL_RESULT_CHARS } from '../../config';

/**
 * Clip a tool result to a character budget, keeping head and tail.
 * The middle is replaced by a marker so the model knows content is missing
 * and can request a specific slice instead of assuming it saw everything.
 *
 * @param result - The raw tool result string
 * @param label - A label for the truncation marker (e.g. 'read_file src/App.tsx')
 * @param maxChars - Character budget (defaults to MAX_TOOL_RESULT_CHARS)
 * @param headRatio - Fraction of budget allocated to the head (default 0.6; use 0.2 for shell output where tail matters most)
 */
export function truncateToolResult(
    result: string,
    label: string,
    maxChars: number = MAX_TOOL_RESULT_CHARS,
    headRatio: number = 0.6,
): string {
    if (result.length <= maxChars) return result;
    const headSize = Math.floor(maxChars * headRatio);
    const tailSize = maxChars - headSize;
    const omitted = result.length - maxChars;
    return [
        result.slice(0, headSize),
        `\n... [${label}: ${omitted} chars omitted of ${result.length} total.`,
        `Use read_file with offset/limit, or search_code, to see a specific region.] ...\n`,
        result.slice(-tailSize),
    ].join('');
}
```

### 2. Create `tests/truncate.test.ts`

Test cases:
- **Under budget passes through unchanged:** input shorter than `maxChars` returns the exact same string
- **Over budget returns correctly sized output:** verify output length is `maxChars` + marker length
- **Head and tail are both present:** first 10 chars of input appear in output, last 10 chars appear in output
- **Label appears in the marker:** the truncation marker includes the provided label
- **Custom headRatio works:** with `headRatio=0.2`, the head portion is 20% and tail is 80%
- **Edge case: exactly at budget:** input length === maxChars passes through unchanged

## Notes

- The `MAX_TOOL_RESULT_CHARS` default of 6000 was chosen to be generous enough for most files while still capping the worst offenders (10k+ char file reads that were being replayed 20+ times).
- The tail-weighted ratio for shell output (0.2 head / 0.8 tail) ensures test failures and build errors are preserved.
- `write_file` arguments (which carry full file content) are handled by the history compactor in Sub-plan 17.3, not here.
