# Sub-plan 17.4: Repair Loop Isolation & Conventions Digest

**Parent plan:** `Plans/17.Token reduction plan - Opus 5 Medium.md` — Steps 4 and 6  
**Complexity:** Medium  
**Prerequisites:** Sub-plan 17.1 (needs `CONVENTIONS_INLINE_DIGEST` config flag)  
**Expected token saving:** ~10-16% combined (2-4% from repair loop + 8-12% from conventions digest)

---

## Objective

Two independent, focused changes bundled together because they are both medium-small and touch entirely different files:

**Part A (Step 4) — Repair Loop Isolation:** When JSON output validation fails, re-invoke the agent on a **fresh thread** with only the repair instructions and the previous raw JSON, instead of replaying the entire bloated ReAct history. This saves 2-4% of tokens and dramatically improves repair success rate (the model's attention is on the schema violation, not buried in tool noise).

**Part B (Step 6) — Conventions Digest:** Instead of telling every dev agent to `read_file` each `.conventions/*.md` file (which then lands in history and gets replayed), inject a compact digest of imperative rules directly into the prompt. This eliminates ~42 convention file reads per run and their subsequent replay cost.

### Implementation Details

#### 1. Modify `src/utils/structured-output.ts` — `buildRepairMessage`

Current signature:
```ts
export function buildRepairMessage(issues: string, originalRequest: string): string
```

New signature:
```ts
export function buildRepairMessage(issues: string, originalRequest: string, previousRaw?: string): string
```

Changes:
- Add optional `previousRaw` parameter
- Include only the first 4,000 chars of `previousRaw` in the repair message (truncate if longer)
- **Stop interpolating `originalRequest`** into the body — it was being re-sent as part of the bloated history, which defeats the purpose. Keep the parameter for signature compatibility but do not use it in the output. The repair message should focus on: (a) what the schema violations are, (b) the previous raw JSON to correct.
- The repair message should look something like:

```
Your previous JSON output had validation errors. Fix these issues and return valid JSON.

Validation issues:
${issues}

Previous output (correct this):
${previousRaw?.slice(0, 4000) ?? '[not available]'}
```

#### 2. Modify `src/conductor/nodes.ts` — `invokeAgent`

Find the `invokeAgent` function (around lines 376-404). Currently the repair re-invokes with `thread_id: threadId` (the same thread), which replays the entire ReAct history.

Change to a **fresh thread** for repair:

```ts
// Instead of reusing threadId:
const repairThreadId = `${threadId}-repair-${attempt}`;
const repairMsg = buildRepairMessage(validation.issues, userMessage, rawJson);
const repairResult = await agent.invoke(
    { messages: [{ role: 'user', content: repairMsg }] },
    { configurable: { thread_id: repairThreadId }, recursionLimit: 2 },
);
```

Key points:
- Use `recursionLimit: 2` to prevent the repair round from starting its own tool loop
- The repair gets a completely fresh context — just the repair instructions and the raw JSON to fix
- `rawJson` is the string that failed validation (capture it from the parse step)

#### 3. Update `tests/structured-output.test.ts`

- Update any existing tests that call `buildRepairMessage` with the old 2-param signature
- Add a test that `buildRepairMessage` with `previousRaw` includes the raw JSON in output
- Add a test that `previousRaw` is truncated to 4,000 chars when longer
- Add a test that `originalRequest` is NOT present in the output body
