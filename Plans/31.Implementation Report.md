## Sub-Plan 31-A: Runtime preflight before side effects (F1, F6)

### Problem
Session 1 ran on Node 19.8.1, the nvm default for the `erez` user. Intake created `ErezSCE/pacman-live-analysis` and pushed `project/pacman-live-analysis`. The architect's first model call then crashed inside LangChain's agent middleware (`langchain/src/agents/errors.ts:123`, `AbortSignal.any`), which needs Node ≥ 20.3. The dependency floor is `@langchain/mcp-adapters` at `engines.node >= 20.10.0`. Nothing checked the runtime, so the run left an orphaned repo behind, which is the trigger for F2.

### Changes

| File | Change |
|------|--------|
| `src/utils/preflight.ts` | **New.** `MIN_NODE_VERSION = '20.10.0'`. `compareVersions()`. `checkNodeRuntime()` checks the version floor and feature-detects `AbortSignal.any`. `configuredModels()` and `findUnpricedModels()` support 31-C. `collectPreflight()` collects `errors[]` + `warnings[]`. `runPreflight()` logs every warning at ERROR level and throws `PreflightError` on any error (fail closed). |
| `src/conductor/run.ts` | `runPreflight()` is the first statement of `runAutonomous`, `runHumanInTheLoop` and `continueRun`, so it runs before `createConductor()` and therefore before intake can create a repo or workspace. |
| `package.json` | `"engines": { "node": ">=20.10.0" }`, so npm warns on an unsupported runtime at install time. |
| `tests/preflight.test.ts` | **New.** 10 tests covering numeric version ordering, the exact session-1 runtime (19.8.1 without `AbortSignal.any`), a missing feature on a new-enough version string, a version below the floor, accepted runtimes, model dedupe, unpriced detection, warnings vs errors, and throw-vs-pass. |

### Notes
- The preflight is a function, not an import-time check (rule 21). Tests and other importers are unaffected.
- Session 2 workaround: the CLI is launched with `PATH=$HOME/.nvm/versions/node/v20.11.1/bin:$PATH`.

## Sub-Plan 31-B: Idempotent `new-repo` creation (F2)

### Problem
`createGitHubRepo()` had no "already exists" path. Any interrupted or crashed intake leaves the repo behind (sessions 0 and 1 both did). The rerun with the same name then dies with `422 name already exists on this account` before any work is done.

### Changes

| File | Change |
|------|--------|
| `src/utils/github-repo-manager.ts` | Creation is wrapped in a `try`. `isNameTakenError()` recognises GitHub's 422 duplicate-name body. `findReusableRepo()` reuses the existing repo only when it carries no work: the requested visibility, ≤ 1 commit on the default branch (409 "repository is empty" counts as zero), and every branch tip equal to the default-branch tip. That is exactly the state an interrupted intake leaves, *including* a pushed system branch. Anything else throws `Repository <o>/<r> already exists and <reason> — choose a different repository name or select "Existing GitHub repository"`. Non-422 errors are rethrown unchanged. |
| `tests/github-repo-manager.test.ts` | 6 new tests: reuse with the system branch at the same tip, reuse of an empty repo (409), refusal on history, refusal on another branch's work, refusal on a visibility mismatch, and non-422 errors rethrown as-is. |

## Sub-Plan 31-F: Graceful shutdown re-enters each run's context (F8)

### Problem
SIGINT/SIGTERM handlers execute outside every `AsyncLocalStorage` scope. The shutdown hooks (three identical copies in `run.ts`) and `gracefulShutdown()` steps 2–4 called `getRunContext()` at signal time, always got `undefined`, and therefore wrote no `state.json` stop reason, no ledger entry and no token report, while still printing "Graceful shutdown complete". This was observed live in session 2.

### Changes

| File | Change |
|------|--------|
| `src/utils/run-context.ts` | New `runWithContextSync(ctx, fn)`: a synchronous re-entry for code that must finish before `process.exit`. |
| `src/utils/crash-handlers.ts` | Registrations store `{ hook?, ctx: getRunContext() }`. New `registerRunShutdown()`. New `saveStoppedRun()`, which writes `state.json` (`cancelled: true`, `_stopReason: 'manual-kill'` for SIGINT/SIGTERM or `'crashed'` otherwise), a `graceful-shutdown` ledger invariant with the run's **actual** phase, and the token-report flush. `gracefulShutdown()` (now exported for tests) runs hook + `saveStoppedRun()` inside each registered context. The dead process-level `getRunContext()` step was removed. |
| `src/conductor/run.ts` | The three copy-pasted 12-line hooks were replaced by `registerRunShutdown()` (autonomous, HITL, continue). Unused `getRunContext` import removed. |
| `tests/crash-handlers.test.ts` | **New.** 4 tests: state + ledger persisted although the signal arrives outside the context, `crashed`/exit 1 on uncaught errors, custom hooks run in their registering context, and single shutdown. |
