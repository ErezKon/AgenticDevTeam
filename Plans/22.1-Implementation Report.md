## Summary

Nine defects from the `pacmanclaude-2026-08-16T15-57-15-320Z` run are fixed. The two that
actually destroyed work were both caused by a mechanism being denominated in the wrong unit or
pointed at the wrong object:

- The tool budget counted **tool calls** when the cost driver is **model turns**, and the whole
  per-category budget system was dead code because `buildAgent()` passed a number instead of an
  object. A Claude agent batching 9–11 reads into one turn therefore spent a 26-unit budget in five
  turns and could no longer write — 3 of 6 dev generations produced zero writes.
- The history compactor's elision placeholder was indistinguishable from real source text, so after
  seeing fifteen of them the model wrote three brand-new files whose entire content was
  `[770 chars elided]`.

Everything else — the blind respawn handoff, the scaffold barrier that never fired, the integrity
gate that deleted four legitimate Playwright specs, and a total Anthropic prompt-cache miss worth
~70 % of the bill — follows the same pattern: a mechanism that was believed to be working, wasn't,
and nothing in the run output said so. Where possible the fix is now accompanied by an assertion
that fails loudly rather than silently.

## Sub-Plan A: Tool budget denominated in turns and categories

**Status**: Completed

### Files Modified

#### 1. `src/agents/_shared/tool-loop-guard.ts`

Substantially rewritten while preserving every existing behaviour (per-`(tool,args)` blocking, free
cached results, cache invalidation on mutation, progress bonus, legacy flat-ceiling mode).

| Addition | Detail |
|----------|--------|
| **Turn counting** | `registerTurn(config)` derives a turn key from `config.metadata.langgraph_step` — one ToolNode execution is exactly one model turn. When absent (direct `.invoke()` in tests, or a framework change) it falls back to time-window batching (`TURN_BATCH_WINDOW_MS = 250`), because parallel calls from one turn arrive within milliseconds of each other. |
| **`turns` budget** | Added to `ToolBudgets`. `isExhausted()` now trips on `turns >= maxTurns` as well as the per-category and hard ceilings. |
| **Retuned defaults** | principal `60/30/14/28`, senior `50/25/12/24`, junior `40/20/12/20` (reads/writes/shell/turns), up from `30/25/10`, `25/20/8`, `20/15/8`. |
| **Partial-override merge** | `resolveToolBudgets()` now merges a JSON override *over* the rank defaults, so `{"junior":{"turns":26}}` changes only the turn ceiling instead of zeroing the other three categories. Invalid JSON logs a warning instead of being silently ignored. |
| **Budget-pressure footer** | Successful tool results carry `[BUDGET: reads 38/60, writes 2/30, turns 17/28 — stop exploring and start writing files.]` above 60 % usage and `[BUDGET CRITICAL: … — write your remaining files and return your final JSON on the NEXT turn.]` above 85 %. ~20 tokens per tool result buys the agent the chance to plan its landing. |
| **`isTerminationDemanded()`** | True once the agent has received `maxPostExhaustionCalls` (default 2) terminal-guidance responses and is still calling tools. |
| **`getUsage()`** | Live `BudgetUsage` snapshot — consumed by the respawn handoff (C2) and by diagnostics. |
| **`ToolBudgetExhaustedError` + `assertNotExhausted()`** | For callers that want a hard failure. |

#### 2. `src/agents/_shared/agent-factory.ts`

- `AgentConfig` gains `toolBudgets?: ToolBudgets`. When present it takes priority over
  `maxToolCalls` and the guard runs in category mode:

```diff
-const { tools: guardedTools, isCeilingReached } = withLoopGuard(cfg.tools, cfg.id, cfg.maxToolCalls);
+const guard = withLoopGuard(cfg.tools, cfg.id, cfg.toolBudgets
+    ? { budgets: cfg.toolBudgets, hardCeiling: LOOP_GUARD_HARD_CEILING,
+        progressBonus: LOOP_GUARD_PROGRESS_BONUS, maxPostExhaustionCalls: MAX_POST_EXHAUSTION_CALLS }
+    : cfg.maxToolCalls);
```

- **A4 — the post-exhaustion spin is ended in the middleware, not in the tool.** When
  `isTerminationDemanded()` is true, `wrapModelCall` sets `tools: []` and `toolChoice: 'none'` on the
  request, so the model physically cannot emit another tool call and must return its final JSON.

  *Design note:* the plan proposed throwing a typed error from the tool wrapper. That does not work —
  LangGraph's `ToolNode` runs with `handleToolErrors: true` and converts a thrown tool error into a
  `ToolMessage`, so the loop would continue exactly as before. Withholding the tools is the only
  mechanism that actually terminates the ReAct loop, and it is documented as such in both the code
  and `AI_Context.md`.

- Exposes `isTerminationDemanded` and `getToolUsage` on the returned agent.

#### 3. `src/agents/developers/dev-agent.builder.ts`

`buildDevAgent` now passes `toolBudgets: resolveToolBudgets(entry.rank, TOOL_BUDGETS_JSON)` instead
of `maxToolCalls: 26 | 22 | 18`. `buildStrongFixerAgent` gets principal budgets plus headroom
(`reads +20`, `writes +10`, `shell +6`) with `turns: STRONG_FIXER_MAX_TOOL_CALLS`.

#### 4. `src/config.ts`

`TOOL_BUDGETS_JSON`, `LOOP_GUARD_HARD_CEILING` and `LOOP_GUARD_PROGRESS_BONUS` **already existed and
were entirely unreferenced** — they were declared for the Sub-Plan 08 budget system that was never
wired up. They are now consumed rather than duplicated. `LOOP_GUARD_HARD_CEILING` default raised
80 → 140 (80 calls is ~8 turns for a model that batches 9–11 per turn). One new variable:
`MAX_POST_EXHAUSTION_CALLS` (default 2).

### Behaviour change worth flagging

`STRONG_FIXER_MAX_TOOL_CALLS` now bounds **model turns**, not individual tool calls. The default (40)
is unchanged but is a materially larger budget than before. Documented in `config.ts`,
`.env.example` and the README table.

## Sub-Plan B: Compaction can no longer corrupt source files

**Status**: Completed

### Files Modified

#### 1. `src/tools/fs/workspace-tools.ts` (B1 — the load-bearing fix)

New exported `checkWritePayload(filePath, content)`, called by **both** `write_file` and `edit_file`
before touching disk. It rejects a payload that is, in its entirety, an orchestrator elision
marker — the legacy `[1204 chars elided]` / `[read_file -> 4210 chars, elided]` forms *and* the new
`⟪ORCHESTRATOR-ELIDED …⟫` form, since checkpoints written before this change still contain the old
shape.

**Deviation from the plan, driven by a test failure.** The plan also specified rejecting content
shorter than 24 characters for source extensions. Implemented, then **removed**: the existing
`gate-integrity` suite has a case writing `export const x = 2;` — 19 characters of perfectly valid
TypeScript. The heuristic rejected real code while adding nothing, because every observed corruption
was the exact marker. The final check is deliberately narrow, and the reasoning is recorded in the
function's doc comment so it is not "helpfully" re-added.

#### 2. `src/agents/_shared/history-compactor.ts`

| Change | Detail |
|--------|--------|
| **B2 — new marker** | `elisionMarker(chars, what)` produces `⟪ORCHESTRATOR-ELIDED 770 chars of the "content" argument — already on disk; NEVER copy this marker into a file⟫`. Used by both `elideBigArgs` and `stubToolContent`. Two properties: it cannot be mistaken for source text, and it carries its own instruction. |
| **B3 — recent write args exempt** | `findRecentWriteTurnIndexes()` identifies the last `HISTORY_KEEP_RECENT_WRITE_ARGS` (2) turns containing a write call; their arguments are never elided. This is exactly the window in which the imitation occurred. |
| **B4 — turn-aware recent window** | `findTurnBoundary(messages, keepTurns)` replaces tool-result counting as the primary control. `recentBoundary = min(turnBoundary, resultBoundary)`, so `HISTORY_KEEP_RECENT_TOOL_RESULTS` survives as a lower bound. |

**Correction to the plan's diagnosis of B4.** The plan asserted the old boundary "lands *inside* the
current turn, stubbing results the model is about to reason over". Reading the code showed that is
not quite right: `findToolResultBoundary` walks back to the parent `AIMessage`, which rescues the
*final* turn. The real defect is that with 11 parallel calls and `keepRecent: 4` it rescues **only**
that one turn — the two turns immediately before it are stubbed. `tests/compaction-write-guard.test.ts`
measures this precisely: 22 of the last 36 messages are stubbed under the legacy rule, 0 under the
turn-aware rule.

#### 3. `src/config.ts`

`HISTORY_KEEP_RECENT_TURNS` (default 3) and `HISTORY_KEEP_RECENT_WRITE_ARGS` (default 2).

## Sub-Plan D: Anthropic prompt caching and cache accounting

**Status**: Completed

### Files Created

#### `src/agents/_shared/prompt-cache.ts`

- `withSystemCacheBreakpoint(systemMessage)` — marks the trailing block of the system message.
  **This one breakpoint also caches the tool schemas**, because Anthropic serialises
  `tools` → `system` → `messages` and caches the longest matching prefix. Verified against
  `@langchain/anthropic@1.5.4`, which passes `SystemMessage.content` straight through to the `system`
  request field and forwards `cache_control` from any content block verbatim
  (`utils/message_inputs.js`).
- `withMessageCacheBreakpoints(messages, budget)` — one breakpoint on the first human message (the
  task + architecture context) and one **rolling** breakpoint on the newest `AIMessage` outside the
  recent window (the stable history prefix).
- Guards: `MIN_CACHEABLE_CHARS = 2000` (a cache write carries a 1.25× surcharge, so marking small
  blocks is a pure loss), idempotent (never stacks breakpoints across turns), operates on a copy,
  and respects Anthropic's 4-breakpoint limit.

## Sub-Plan E: Streaming sanitiser completed

**Status**: Completed

#### `src/agents/_shared/history-compactor.ts`

- **E1** — the sanitiser previously kept `tool_use` blocks that had an `id` but `input: ""`, which is
  the shape of *every* Anthropic tool call in the dumps. The model's own history therefore showed it
  calling `read_file` with no arguments. It now drops such a block when a matching `tool_calls` entry
  exists (the adapter re-materialises it), and otherwise **reconstructs `input` from the sibling
  `input_json_delta` blocks** rather than forwarding an argument-less call — which matters for
  histories restored from a checkpoint where `tool_calls` did not survive.
- **E2** — new `normaliseAIMessageForState()`, wired to an `afterModel` middleware hook, cleans the
  fresh `AIMessageChunk` **before** it is persisted. `sanitizeStreamingContentBlocks` works on a copy
  by design, so residue accumulated in the checkpoint and was re-scanned every turn — the cause of
  the `dropped 2 … dropped 31` monotonic growth. `tests/stream-sanitiser.test.ts` asserts the counter
  is now `[0,0,0,0,0]` across five turns and `[4,8,12,16,20]` without normalisation.

## Sub-Plan F: Scaffold barrier and integrity gate

**Status**: Completed

#### 1. `src/agents/developers/dispatcher.ts` (F1)

```diff
-return a.taskType === 'chore' || /\/chore\/scaffold$/i.test(a.branchName ?? '');
+export const SCAFFOLD_BRANCH_RE = /(^|\/)chore\/scaffold$/i;
+return a.taskType === 'chore' || SCAFFOLD_BRANCH_RE.test(a.branchName ?? '');
```

The old pattern required a leading slash; the Team Leader emits `chore/scaffold` un-prefixed. Branch
classification also changed from `every(isScaffoldAssignment)` to a new
`isScaffoldBranch(branch, assignments)` — branch name first, then `some(...)` — because a single
`refactor`-typed assignment sharing the scaffold branch previously disabled the barrier for the whole
run. A `Branch classification: N scaffold [...], N parallel, N serialised chain(s)` line is now
logged **unconditionally**, so a mis-classification is one grep away instead of being inferred from
an absent log line.

#### 2. `src/conductor/gate-integrity.ts` (F2/F3)

- `isBrowserDrivenTest(relPath, content)` — detects Playwright/Cypress/WebdriverIO/Puppeteer specs by
  path (`**/e2e/**`, `*.e2e.spec.*`, `cypress/**`), by import, or by driver API use
  (`page.goto(`, `cy.visit(`). Such files skip `no-product-import` and `subject-not-in-product`
  entirely and are instead checked for the presence of any assertion — a new `no-assertions` reason.
- `trivialTestSeverity(reason)` — `tautological-assertion`, `single-arithmetic-test` and
  `no-assertions` stay `critical`; the heuristic import-graph reasons drop to `major`.

#### 3. `src/conductor/pr-workflow.ts` (F3)

Findings are pushed with `trivialTestSeverity(tf.reason)`. Deletion now requires
`GATE_INTEGRITY_DELETE_TRIVIAL_TESTS` (default **false**) *and* a `critical` severity, and every body
is copied to `outputs/<run>/deleted-tests/<branch>/` by a new `archiveDeletedTest()` before
`unlinkSync`. Heuristic findings log `… are heuristic — reported, not deleted: <files>`.
