## Step 1: Token Tracker Enhancements (`token-tracker.ts`)

### Interface Changes
- `AgentUsageSummary`: Added `cacheReadTokens: number` and `cacheCreationTokens: number`.
- `RunUsageSummary.byPhase`: Added `cacheReadTokens` and `cacheCreationTokens` to each phase entry.
- `RunUsageSummary.byModel`: Added `cacheReadTokens` and `cacheCreationTokens` to each model entry.

### Aggregation Logic (`getRunSummary()`)
The loop now extracts `cacheRead` and `cacheWrite` from each ledger record (defaulting to 0) and accumulates them into the agent, phase, and model maps alongside the existing input/output/total counters.

### WebSocket Event (`tokens:update`)
The event payload now includes:
```typescript
totalCacheReadTokens: summary.totalCacheReadTokens,
totalCacheCreationTokens: summary.totalCacheCreationTokens,
cacheHitRate: summary.cacheHitRate,
```

## Design Decisions

1. **Shared `estimateCost()`**: Eliminated the duplicated `estimateCostLocal()` in favor of the cache-aware `estimateCost()` from `cost.ts`, ensuring consistent pricing across the report and the budget system.

2. **Chart.js direct (no wrapper)**: Used `chart.js` directly rather than `ng2-charts` to avoid an extra dependency and maintain consistency with the HTML report which also uses Chart.js directly via CDN.

3. **Cache savings as delta**: `cacheCost` in `AgentCostRow` is computed as `listPrice - billedPrice`, giving a clear savings metric per agent without double-counting.

4. **Conditional rendering**: All cache-related UI elements (`*ngIf="totalCacheReadTokens > 0"` etc.) are hidden when cache data is zero, keeping the UI clean for runs without prompt caching.
