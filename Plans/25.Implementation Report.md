# Sub-Plan 26-04: Correctness Fixes — Implementation Report

> **Date:** 2026-08-18
> **Scope:** 13 targeted behavioral bug fixes across 7 source files
> **Verification:** `tsc --noEmit` passes; `npm run test:unit` passes (84 suites, 1,344 tests)

---

## Summary

Sub-Plan 26-04 addresses 13 correctness bugs identified by the codebase audit that silently degrade pipeline quality. These include fail-open security gates, stale iteration data causing looping, lost assembly bugs, summary data computed after the string was already built, and a worktree disposal bug that always took the wrong branch.

---

## Changes by Step

### Step 1: acceptance-gate.ts — Filter test counting to executed tests only

**Problem:** `MIN_TEST_REPORTS` threshold counted LLM-claimed and quality-gate test reports, allowing the acceptance gate to pass even with zero real test execution.

**Fix:** Added `source === 'executed'` filter so only test reports from actual runners count toward the minimum.

### Step 2: acceptance-gate.ts & nodes.ts — Read integrityFindings from PR records

**Problem:** The INTEGRITY acceptance criterion searched `state.bugs` for `TAMPER-` prefixed IDs, but no code ever created bugs with that prefix. The integrity findings are stored on `pullRequests[].integrityFindings` (populated by pr-workflow.ts).

**Fix:** Changed `evaluateAcceptance()` and the finalize node's summary to read from `state.pullRequests[].integrityFindings` instead. Updated the corresponding test.

### Step 3: security-gates.ts — Filesystem walk fallback on git failure

**Problem:** When `git ls-files` failed (non-git workspace), `scanForSecrets()` returned an empty array — silently skipping the entire secret scan.

**Fix:** Added a `walkFilesForSecretScan()` helper that recursively walks the filesystem (pruning `node_modules`, `.git`, `dist`, etc.) and returns relative paths. On git failure, the scan now uses this fallback instead of returning empty.

### Step 4: security-gates.ts & nodes.ts — Fail-closed on sub-gate exceptions

**Problem:** Each sub-gate (secrets, dependency audit, licence check) had `catch` blocks that logged warnings and continued. Any exception left findings empty, producing `passed: true` (fail-open).

**Fix:** Errors are now collected in an `errors[]` array, and `passed` is `false` when any error occurred. The `SecurityReport` interface gains an optional `errors` field. The caller in `nodes.ts` propagates these errors to `verificationErrors`.

### Step 5: graph.ts — Filter currentIterationFailures by iterationIndex

**Problem:** `currentIterationFailures()` considered all test reports regardless of which bugfix iteration produced them. Stale failures from earlier iterations caused unnecessary bugfix looping.

**Fix:** Added `iterationIndex` filtering (matching the pattern already used by `afterE2eRouter`). Reports with `iterationIndex !== currentIteration` are excluded. Updated two graph-routing tests to provide matching `iterationIndex` values.

### Step 6: nodes.ts — SECURITY_GATES_ENABLED flag (no change needed)

**Status:** Already resolved. The `SECURITY_GATES_ENABLED` flag is checked inside `runSecurityGates()` at line 441 of `security-gates.ts`. The unused import in `nodes.ts` was already removed in Sub-Plan 26-01.

### Step 7: nodes.ts — Surface assembly-gate bugs in development node return

**Problem:** `assemblyBugs` were created inside a nested `if` block but never added to the return object. Bugfix triage never saw assembly failures.

**Fix:** Hoisted `assemblyBugs` to function scope (typed as `Bug[]`) and added `bugs: assemblyBugs` to the development node's return object.

### Step 8: nodes.ts — Move summary sections before summaryText = summary.join()

**Problem:** Acceptance blockers, PR/branch counters, and phase timeline were pushed to `summary[]` AFTER `summaryText = summary.join('\n')` was computed. They never appeared in the summary artifact or log output.

**Fix:** Moved all three sections (acceptance blockers, PR counters, phase timeline) above the `summary.join()` call. Removed the duplicate code that was previously below the token usage report.

### Step 9: pr-workflow.ts — Replace prStatus sentinel with mergeBlocked variable

**Problem:** `prStatus` was overloaded as both a PR status tracker and a merge-blocking sentinel. Multiple checks set `prStatus = 'open'` to prevent merge, conflating "genuinely open" with "blocked for a specific reason."

**Fix:** Introduced `let mergeBlocked: string | null = null`. Each blocking check sets `mergeBlocked` to a descriptive reason. The merge attempt only runs when `mergeBlocked === null`. The integrity-findings check was also consolidated into this flow.

### Step 10: pr-workflow.ts — Fix worktree disposal with correct merge tracking

**Problem:** The `finally` block tested whether the local branch still existed to decide merge success. But the local branch was deleted AFTER the check, so `branchStillExists` was always `true` — meaning the worktree was ALWAYS preserved for salvage, even on successful merges.

**Fix:** Added `let wasMerged = false` before the try block (outside block scope). Set `wasMerged = true` alongside `prStatus = 'merged'`. The finally block uses `wasMerged` to choose the disposal path. Also moved local branch deletion before worktree removal.

### Step 11: file-change-reconciliation.ts — Guard against git error strings

**Problem:** `gitExec()` returns `"Error: ..."` strings on failure. These were split on newlines and added to `actualPaths` as if they were filenames, corrupting the reconciliation result.

**Fix:** Added `!diffOutput.startsWith('Error:')` and `!untrackedOutput.startsWith('Error:')` guards before processing the output.

### Step 12: context-builder.ts — Demote force-truncation log to warn

**Problem:** `log.error()` was emitted when context exceeded the budget after clipping. This was misleading because (a) no actual force-truncation was implemented, and (b) models handle slight overages gracefully.

**Fix:** Changed `log.error(...)` to `log.warn(...)` with updated message text.

### Step 13: nodes.ts — Wrap finalizeNode reports in try/catch with guaranteed state writes

**Problem:** If any report-building code in `finalizeNode` threw (e.g., traceability, token usage report, timeline), `writeStateSnapshot()` and `writeRunManifest()` would never execute — breaking continue-run capability.

**Fix:** Wrapped the entire report-building section in a try/catch block. Hoisted `traceReport`, `filesDelivered`, `phantomFileChanges`, `prCounts`, `budget`, and timeline variables outside the try. On catch, logs the error and continues to the state writes which now execute unconditionally.
