# Plan 16 — Implementation Report

## Sync the workspace to the merged system branch (fixes A1)

**Finding addressed:** A1 — The workspace QA and DevOps operate on never receives the merged developer code.

**Root cause:** `executePRWorkflow` does all development inside isolated git worktrees and squash-merges PRs on the remote via `octokit.pulls.merge`. Nothing ever fast-forwards the main checkout at `state.workspacePath`, so `qaNode` and `devopsNode` see a tree containing only `docs/` artifacts and `.conventions/` — none of the merged application source. QA burned its entire tool budget exploring an empty directory, and DevOps wrote configs for a project it couldn't see.

---

### 1. New module: `src/utils/git-exec.ts`

Extracted `gitExec`, `gitPush`, and `findGitRoot` from their duplicated definitions in `nodes.ts` (lines 73-96) and `pr-workflow.ts` (lines 73-101, 203-211) into a single shared module. All three functions are now imported from one place.

## Sub-Plan 2 — Assignment lifecycle: never redo completed work (fixes A2)

**Finding addressed:** A2 — The bug-fix loop re-runs every already-completed assignment.

**Root cause:** `assignments` uses the **append** reducer, so after a bug-fix triage round the state holds the original assignments AND the new fix assignments. `developmentNode` called `dispatchDevelopers(apiKey, state.assignments, ...)` with the entire accumulated list, re-running every completed assignment on every bug-fix iteration — up to 4x the intended development cost. Additionally, `fileChanges` was injected as full pretty-printed JSON (`JSON.stringify(state.fileChanges, null, 2)`) into every developer's context prompt, growing without bound.

---

### Changes Made

#### 1. New module: `src/conductor/assignment-policy.ts`

Pure functions for assignment lifecycle management:

| Function | Purpose |
|----------|---------|
| `selectPendingAssignments(assignments, completedIds)` | De-duplicates by id (first occurrence wins), then removes completed ids. Returns only assignments still needing dispatch. |
| `completedIdsFromPullRequests(prs)` | Extracts assignment ids from PRs with status `merged` or `approved`. Excludes `open`, `closed`, and `escalated_open`. |
| `namespaceBugfixAssignments(assignments, iteration)` | Prefixes ids with `BUGFIX-<n>-` to avoid collisions. Rewrites intra-batch `dependsOn` entries; leaves external refs unchanged. |
| `dedupeBugs(bugs)` | De-duplicates bugs by id (first occurrence wins). Bugs use append reducer, so duplicates accumulate across iterations. |

## Sub-Plan 3 — Make QA E2E reachable and verify deployment for real (fixes A3, A5)

**Findings addressed:**
- A3 — QA E2E can never run (the E2E block was inside `qaNode`, gated on `state.devopsPlan?.serviceUrls` which was always `null` because DevOps hadn't run yet).
- A5 — `docker-runner.ts` is dead code; deployment status is an LLM self-report (nothing imported docker-runner.ts, and `buildStatus`/`runStatus`/`serviceUrls` came straight from the DevOps agent's unverified JSON).

**Root cause (A3):** The graph edges were `qa -> devops -> finalize`, so `devopsPlan` was always `null` when `qaNode` ran. The Playwright MCP integration, the `qa-e2e` agent, and the E2E section of the README were unreachable code.

**Root cause (A5):** `src/executor/docker-runner.ts` exported `buildImage`, `runContainer`, `healthCheck`, and `stopContainer` (208 lines, dockerode-based) but nothing in `src/` imported them. `devopsPlan` fields came from the DevOps agent's JSON response with no actual verification that images build, containers start, or services answer.

### Changes Made

#### 1. Added `'e2e'` to `PhaseName` schema

Updated `src/agents/_shared/schemas/phase.schema.ts` to include `'e2e'` in the `PhaseNameSchema` enum, making it a valid pipeline phase.

#### 2. New module: `src/conductor/devops-verify.ts`

Implements actual deployment verification using the previously-dead `docker-runner.ts`:

| Function | Purpose |
|----------|---------|
| `chooseDeploymentMode(workspacePath)` | Picks deployment strategy: `'compose'` (docker-compose.y[a]ml), `'dockerfile'` (Dockerfile only), or `'none'`. |
| `deriveServiceUrls(composePsJson, hostname?)` | Parses `docker compose ps --format json` NDJSON output into `{service, url}[]`. Skips services with no published port. |
| `verifyDeployment(workspacePath, projectSlug)` | Builds and runs what the DevOps agent wrote, health-checks it. Returns verified `buildStatus`, `runStatus`, `serviceUrls`, `healthChecks`, `containerNames`, and `logs`. Never throws: Docker-less environments degrade to `buildStatus: 'skipped'`. |
| `teardownDeployment(workspacePath, containerNames)` | Stops and removes containers started by `verifyDeployment`. Uses `docker compose down` for compose mode, `stopContainer()` for dockerfile mode. |

The module imports and uses `buildImage`, `runContainer`, `healthCheck`, and `stopContainer` from `src/executor/docker-runner.ts` -- making it no longer dead code.

Deployment modes:
- **compose**: validates with `docker compose config -q`, then `docker compose up -d --build`, then `docker compose ps --format json` -> `deriveServiceUrls`, then health-checks each URL.
- **dockerfile**: calls `buildImage()`, parses `EXPOSE` ports from the Dockerfile, maps them to host ports starting at `DEVOPS_VERIFY_BASE_PORT`, calls `runContainer()`, then health-checks.
- **none**: returns all-`skipped`.

Gated by `DEVOPS_VERIFY_ENABLED` (default `true`). When disabled or Docker is unreachable, returns all-`skipped` and logs at info.

## Sub-Plan 4 -- Multi-language quality gates that actually gate (fixes A6)

**Finding addressed:** A6 -- The pre-PR quality gate is npm-only.

**Root cause:** `ensureDepsAndRunTests` (`pr-workflow.ts:152-201`) was npm-only: no `package.json` or no real `scripts.test` returned `null`, meaning no gate at all. ## Sub-Plan 5 -- Validate agent output against its Zod schema, with one repair round (fixes A7)

**Finding addressed:** A7 -- Agent output is never validated against its schema.

**Root cause:** `buildAgent` accepts `cfg.responseFormat` (a Zod schema) but only stringifies it into the prompt via `z.toJSONSchema()` -- it is **never** passed to `createReactAgent` and never used to `parse`. `invokeAgent` JSON-parses with three fallbacks (direct parse, code-fence extraction, first `{...}` run) and returns whatever comes out as `any`. Every consumer is written defensively with `?? []` / `?? 0` defaults, which converts schema violations into silent zeros rather than errors. A `testReport` missing `status` silently becomes a pass. The same 3-strategy JSON parse was duplicated in `pr-workflow.ts` for dev and reviewer outputs.

## Sub-Plan 7 -- Run budget guard and graceful degradation (fixes the A9 cost ceiling gap)

**Finding addressed:** A9 -- There is no cost or wall-clock ceiling. A pathological run can consume the entire monthly quota; nothing degrades or aborts.

**Root cause:** Run 6 spent ~8 h and 5,115 LLM calls with no ceiling of any kind. Cost-shaping knobs (`MAX_REVIEW_ITERATIONS`, `MAX_BUGFIX_ITERATIONS`, `PR_TEST_REPAIR_ATTEMPTS`) were imported as static constants from `config.ts` and could not change mid-run. The `estimateCost` function was defined inside `finalizeNode` and could not be reused by a budget module. There was no mechanism to shed expensive optional work (extra review rounds, second reviewers, repair attempts, bug-fix loops) as a run approached a resource ceiling.

---

### Changes Made

#### 1. New module: `src/utils/cost.ts`

Extracted `estimateCost` from `finalizeNode` into a shared module:

| Function | Purpose |
|----------|---------|
| `estimateCost(model, inputTokens, outputTokens)` | Estimated USD cost for one model's token counts. Unknown models cost $0. |
| `estimateRunCost(summary)` | Estimated USD cost for a whole `RunUsageSummary` (sums across agents). |

#### 2. New module: `src/utils/run-budget.ts`

Implements the budget guard with a degradation ladder:

| Function | Purpose |
|----------|---------|
| `computeBudgetLevel(utilisation)` | Pure: maps utilisation to level. warn >= 0.70, degrade >= 0.90, stop >= 1.0. |
| `startRunBudget()` | Called once at run start (from `intakeNode`) to stamp the wall-clock origin. |
| `getBudgetStatus()` | Returns `BudgetStatus` with `level`, `usedTokens`, `maxTokens`, `estCostUsd`, `maxCostUsd`, `elapsedMs`, `maxWallMs`, `binding`, and `utilisation`. Logs each level transition exactly once. |
| `getEffectiveLimits()` | Returns cost-shaping limits adjusted for the current budget level (degradation ladder). |
| `_resetRunBudget()` | Reset for testing. |
| `_setRunStartMs(ms)` | Override run start time for testing. |

**Degradation ladder:**

| level | reviewIterations | reviewers | repairAttempts | bugfixIterations | new branch workflows |
|-------|------------------|-----------|----------------|------------------|----------------------|
| ok | config | 2 | config | config | yes |
| warn | config | 2 | config | config | yes (log WARN once) |
| degrade | 1 | 1 | 0 | 0 | yes |
| stop | 1 | 0 | 0 | 0 | no |

**Budget status computation:**
- Computes per-limit utilisation for tokens, cost, and wall-clock time (0 = disabled -> 0 utilisation)
- The binding limit is whichever has the highest utilisation
- When all limits are 0 (disabled), binding stays 'none' and utilisation stays 0
- Level transitions are logged exactly once: `warn` for warn/degrade, `error` for stop

## Sub-Plan 8 -- Observability: live event bus, state snapshots, and run manifests (fixes A9)

**Root cause:** The only event mechanism was a file-scoped `broadcast()` function in `src/index.ts` used for WebSocket messages. ## Sub-Plan 9 — HITL Improvements: Checkpointer, Enhance, and Run Resumption

**Finding addressed:** A4 — HITL defects: no checkpointer, "enhance" feedback is a no-op, run cannot be resumed after a crash.

**Root causes:**
1. The graph used an implicit in-memory checkpointer with no option for file-backed persistence. A crashed or interrupted HITL run lost all state.
2. The "enhance" HITL path stored feedback in the `approvals` array but no node ever read it — the same phase output was returned unchanged.
3. The "deny" HITL path exited the loop in the CLI but did not route the graph to finalize, leaving it in a partial state.
4. There was no `resumeRun` function to reconstruct a session from a persisted checkpoint.

---

### Changes Made

#### 1. State additions — `src/conductor/state.ts`

| Field | Type | Reducer | Purpose |
|-------|------|---------|---------|
| `pendingRerun` | `PhaseName \| null` | replace | When set, the named phase will re-run itself once (cleared by the node at re-entry). |
| `phaseFeedback` | `Record<string, string[]>` | merge-concat | Accumulated user feedback per phase. Entries concatenate across enhance rounds. |
| `cancelled` | `boolean` | replace | Set to `true` when a HITL deny is issued, so the graph routes to finalize. |

#### 2. Graph parameterisation — `src/conductor/graph.ts`

- **Rewritten** to export `ConductorOptions` interface: `{ mode?, checkpointer?, outputPath? }`.
- `buildConductorGraph(opts)` builds the `StateGraph`, resolves the checkpointer (explicit -> FileCheckpointer if `CHECKPOINT_PERSIST` -> MemorySaver fallback), and compiles with `interruptBefore` in human mode.
- Every HITL phase edge now uses `rerunRouter(phase, next)` — a conditional edge that checks `state.pendingRerun === phase` to loop back, and `state.cancelled` to short-circuit to finalize.
- `afterQaRouter` and `afterE2eRouter` now check `state.cancelled` before their existing logic.

#### 3. File-backed checkpointer — `src/conductor/file-checkpointer.ts` (new)

- `FileCheckpointer extends MemorySaver` — overrides `put` and `putWrites` with write-through to `<outputPath>/checkpoints.json`.
- On construction, loads existing checkpoint data from disk if present.
- Gated behind `CHECKPOINT_PERSIST=true` in config (default `false`).

#### 4. HITL decision type and session — `src/conductor/run.ts`

- **`HitlDecision`** type exported: `'approve' | 'deny' | 'enhance'`.
- `RunSession.resume(decision, feedback?)` accepts `HitlDecision` or `boolean` (backward-compat: `true` -> approve, `false` -> deny).
- **Approve**: adds approval to state, invokes graph continuation.
- **Enhance**: validates non-empty feedback, sets `pendingRerun` and `phaseFeedback` in state update, invokes graph (which re-runs the phase with feedback injected into its prompt).
- **Deny**: sets `cancelled: true`, marks run status as `'cancelled'`, invokes graph (which routes through finalize).
- **`resumeRun(threadId, outputPath, opts?)`**: new export that reconstructs a `FileCheckpointer` from `outputPath`, builds a conductor, and returns a `RunSession` (HITL) or final state (autonomous).

#### 5. Node feedback injection — `src/conductor/nodes.ts`

- Added `buildFeedbackSection(state, phase)` helper — builds a `## Reviewer Feedback -- you MUST address this` section from `state.phaseFeedback[phase]`.
- Added `checkRerun(state, phase, logger)` helper — returns partial state update to clear `pendingRerun` when set.
- Updated all 9 HITL nodes (`codebaseAnalyzerNode`, `architectNode`, `productManagerNode`, `dbaNode`, `teamLeaderNode`, `developmentNode`, `qaNode`, `devopsNode`, `e2eNode`):
  - Call `checkRerun()` at entry; spread result into return.
  - Call `buildFeedbackSection()` and inject into context prompt (compact mode: as highest-priority section).
- `finalizeNode`: uses `state.cancelled` to choose between `'completed'` and `'cancelled'` for `tokenTracker.setRunStatus`, `generateTokenReport`, and `writeRunManifest`.

## Sub-Plan 11 -- Security and dependency-audit gate (new capability)

**Finding addressed:** No security checking exists anywhere in `src/`. The generated product is committed and merged with zero secret, vulnerability, or licence checks.

**Root cause:** The pipeline had no secret scanning, no dependency vulnerability audit, and no licence compliance checking. Agents could and did write `.env` files and hard-code values; credentials could land in tracked files and be merged without detection. The only defence was human review, which was unreliable for security-sensitive patterns.

---

### Changes Made

#### 1. New module: `src/conductor/security-gates.ts`

Implements three independent security checks and a combined runner:

| Function | Purpose |
|----------|---------|
| `scanForSecrets(workspacePath)` | Regex sweep for hard-coded credentials over git-tracked text files. Offline and dependency-free. Skips `.env.example`, `.conventions/`, `.worktrees/`, `node_modules/`, lock files, and anything git does not track. |
| `auditDependencies(workspacePath, opts?)` | Per-stack dependency audit. Reuses `detectStacks` from `quality-gates.ts`. Every command is optional; a missing tool yields no findings. Accepts injected `exec` seam for testing. |
| `checkLicences(workspacePath)` | Flags dependency licences matching `LICENCE_DENYLIST` (npm `license` fields only, for now). Handles regular and scoped (`@org/pkg`) packages. |
| `runSecurityGates(workspacePath, opts?)` | Runs all three checks. Returns `{ findings, passed }`. `passed = no critical findings`. Gated by `SECURITY_GATES_ENABLED` (default `true`). |
| `synthesiseSecurityBugs(report)` | Converts critical/major findings into `Bug` objects when `SECURITY_GATE_BLOCKING=true`. Uses the finding's stable `id` so `dedupeBugs` (Sub-Plan 2) handles repeats. |
| `securityReportToMarkdown(report)` | Renders a `SecurityReport` as a markdown table for PR descriptions and artifacts. |

**Secret patterns** (exported as `SECRET_PATTERNS` for testability):

| Pattern | What it detects |
|---------|----------------|
| `AKIA[0-9A-Z]{16}` | AWS access key ID |
| `-----BEGIN (RSA/EC/OPENSSH/DSA )?PRIVATE KEY-----` | Private keys |
| `gh[pousr]_[A-Za-z0-9]{36}` | GitHub tokens |
| `xox[baprs]-[A-Za-z0-9-]{10,}` | Slack tokens |
| `eyJ...` (3-part base64) | JWT |
| Generic: `(api_key/secret/password/token) := "value"` | Generic secrets (excludes placeholders like `changeme`, `your-*`, `${...}`, `<...>`, `example*`, `placeholder*`) |

**Audit commands by stack:**

| Stack | Command | Deep-only? |
|-------|---------|------------|
| node | `npm audit --json --audit-level=high` | No |
| python | `pip-audit -f json` | No |
| go | `govulncheck ./...` | No |
| dotnet | `dotnet list package --vulnerable --include-transitive` | No |
| maven | `mvn -B -q org.owasp:dependency-check-maven:check` | Yes (`SECURITY_DEEP_AUDIT=true` only) |

**Severity mapping:** Any secret -> `critical`. Vulnerability `critical`/`high` -> `critical`, `moderate` -> `major`, else `minor`. Denied licence -> `major`.

**Redaction discipline:** All log lines and report details contain the match **location** and **pattern name**, never the matched value. Asserted in tests.

## Sub-Plan 12 -- Repo hygiene and an honest shell sandbox (fixes A11)

**Finding addressed:** A11 -- Repo hygiene and a false sandbox claim.

**Root causes:**
1. `deployAllConventionsToWorkspace` copied all 16 convention `.md` files (~150 KB) into `<workspace>/.conventions/` and pipeline nodes ran `git add .`. The root `.gitignore` ignored `.worktrees/` but not `.conventions/`, and in `new-repo`/`existing-repo` mode the generated repo had no inherited `.gitignore` -- so scaffolding shipped to the customer inside the delivered product.
2. Worktree cleanup (`pr-workflow.ts`) was inside a `try/finally` that was only entered after the worktree was created, so a throw during creation leaked the directory. Stale worktrees from previous runs were never swept at run start.
3. `shell-tools.ts` documented Docker sandboxing and an `ALLOW_HOST_SHELL` escape hatch. The implementation was `child_process.exec` on the host, unconditionally; `ALLOW_HOST_SHELL` appeared nowhere else in the repo. No denylist, no timeout clamping.

## Sub-Plan 13: Offline Determinism — LLM Cassettes + Local GitHub Stand-In

**Finding addressed:** A12 — The only way to test the pipeline is a full end-to-end run against a rate-limited LLM gateway and live GitHub, making CI impractical.

**Root cause:** Every pipeline run requires real OAuth credentials, a live LLM endpoint, and a GitHub PAT with repo scope. There is no way to record, replay, or mock these interactions, so tests are slow, flaky, and expensive.

---

### Changes Made

#### 1. New module: `src/utils/llm-cassette.ts`

Record/replay wrapper for LLM HTTP traffic. Sits inside `throttledFetch` (wraps `oauthFetch`) so recordings capture real gateway responses and replays skip throttle cooldowns entirely.

| Export | Purpose |
|--------|---------|
| `cassetteFetch(inner)` | Wraps a fetch function with record/replay logic. In `record` mode, passes through to `inner`, buffers the response, appends a redacted JSONL line to the cassette file. In `replay` mode, returns a synthesised `Response` from the cassette. |
| `buildCassetteKey(url, method, body)` | SHA-256 hash of `{url, method, body}` with volatile fields (`thread_id`, `run_id`, `session_id`, `stream`, `stream_options`) stripped for stability across re-runs. |
| `redactHeaders(headers)` | Drops `Authorization` and any header matching `/token\|secret\|key\|password\|credential\|auth/i`. |
| `redactBody(value)` | Recursively replaces sensitive object keys with `***REDACTED***`. |
| `resolveCassettePath(name?)` | Resolves `tests/cassettes/<name>.jsonl` (supports `.jsonl.gz`). |
| `getCassetteStats()` | Returns `{mode, recorded, replayed, misses}` counters. |
| `_resetCassette()` | Resets internal state (for testing). |
| `_loadFromContent(content)` | Loads JSONL content into replay store (for testing). |

**Storage format:** `tests/cassettes/<CASSETTE_NAME>.jsonl` — one JSON object per line. JSONL so a crashed recording is still usable and diffs are reviewable.

**Security:** All cassettes are redacted on write — Authorization headers and sensitive fields are stripped before any data reaches disk.

#### 2. New module: `src/utils/github-local.ts`

Minimal local stand-in for the GitHub REST API, backed by a bare git repo used as `origin`.

| Export | Purpose |
|--------|---------|
| `createLocalGitHub(bareRepoPath)` | Returns an `OctokitLike` object implementing: `pulls.create`, `pulls.merge` (real `git merge --squash`), `pulls.get`, `issues.createComment`, `git.deleteRef`, `repos.get`, `repos.createForAuthenticatedUser`, `users.getAuthenticated`. |
| `GITHUB_MODE` | `'live'` (default) or `'local'` (reads `process.env.GITHUB_MODE`). |
| `OctokitLike` (type) | Minimal interface matching what `pr-workflow.ts` and `github-repo-manager.ts` consume. |

`pulls.merge` performs a real `git merge --squash` in a scratch clone and pushes the result back to the bare repo, so the merged tree behaves exactly as it does against real GitHub.
