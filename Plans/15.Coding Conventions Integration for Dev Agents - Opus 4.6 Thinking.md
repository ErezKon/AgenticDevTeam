# Coding Conventions Integration for Dev Agents

Inject coding convention/best-practice files into all coding agents (developers, reviewers, QA, DevOps) using a read-file tool approach, where convention files are copied to the project workspace and agents are instructed to read them before writing code.

---

## Design Overview

### Approach: Read-File Tool with Smart Mapping

Convention files from `src/Coding Conventions, Best Practices/` are copied into each generated project's workspace (under `.conventions/`) at the start of the development phase. Agent prompts are updated with explicit instructions to `read_file` the relevant convention files before writing any code. Which files to read is determined by **combining** the agent's registered languages with the Architect's tech stack decisions.

### Why Read-File Over Prompt Injection

- **Token efficiency**: Convention files range from 4KB (Universal) to 34KB (SCSS). Injecting all relevant files into every prompt would add 20-60KB of tokens per agent call. With the read-file approach, the agent reads them once (using an existing tool call) and the cost is bounded.
- **Agent compliance**: The prompt instruction is explicit and mandatory — "BEFORE writing any code, you MUST read the following convention files." This is reinforced in `<critical_rules>`.
- **Freshness**: Since files are in the workspace, agents can re-read them if needed (e.g., before a second assignment or a review fix iteration).

### File Selection Logic

Two sources combined, deduplicated:

1. **Agent languages** (static, from registry): e.g., a `junior-react` agent with `languages: ['React']` maps to `React.md`, `JavaScript.md`, `TypeScript.md`
2. **Tech stack decisions** (dynamic, from Architect): e.g., `{layer: 'frontend', choice: 'Angular'}` maps to `Angular.md`, `TypeScript.md`
3. **Always included**: `Universal.md` (applies to all languages)

### Agents in Scope

| Agent Type | Gets Conventions? | Why |
|---|---|---|
| Developer (principal/senior/junior) | Yes | Writes production code |
| Reviewer | Yes | Reviews code against standards |
| QA Unit/Integration | Yes | Writes test code |
| QA E2E (Playwright) | Yes | Writes test code |
| DevOps | Yes | Writes CI/CD and infra config |
| Architect | No | Doesn't write code; designs |
| Product Manager | No | Doesn't write code |
| DBA | No | Schema design, not code |
| Team Leader | No | Task assignment, not code |
| QA Lead | No | Test plan, not code |
| Codebase Analyzer | No | Analysis, not code |

## Sub-Plan 1: Convention Mapping & Deployment Utility

**Goal**: Create a utility module that (a) maps languages/tech choices to convention file names, and (b) copies the relevant files into the project workspace.

**File**: `src/utils/coding-conventions.ts` (new)

### Changes

1. **Create language-to-file mapping** — a `Map<string, string[]>` that maps known language/framework names (as used in the dev registry and tech stack decisions) to the corresponding `.md` file names:
   ```
   'React'         → ['React.md', 'JavaScript.md', 'TypeScript.md']
   'Angular'       → ['Angular.md', 'TypeScript.md']
   'Vue' / 'Vue.js' → ['Vue.md', 'JavaScript.md', 'TypeScript.md']
   'TypeScript'    → ['TypeScript.md', 'JavaScript.md']
   'JavaScript'    → ['JavaScript.md']
   'C#/.NET' / 'C#' → ['CSharp.md']
   'Java/Spring' / 'Java' → ['Java.md']
   'Go'            → ['Go.md']
   'Python' / 'Python/FastAPI/Django' → ['Python.md']
   'Node.js/Express' / 'Node.js' → ['JavaScript.md', 'TypeScript.md']
   'HTML/CSS'      → ['HTML.md', 'CSS.md']
   'HTML'          → ['HTML.md']
   'CSS'           → ['CSS.md']
   'SASS' / 'SCSS' → ['SCSS.md', 'CSS.md']
   'Tailwind'      → ['CSS.md']
   'Svelte'        → ['JavaScript.md', 'TypeScript.md']
   'C'             → ['C.md']
   'C++'           → ['CPlusPlus.md']
   ```

2. **`resolveConventionFiles(agentLanguages: string[], techStack: TechDecision[]): string[]`** — combines both sources, deduplicates, always includes `Universal.md`. Returns sorted array of file names.

3. **`deployConventionsToWorkspace(workspacePath: string, fileNames: string[]): string[]`** — copies the specified `.md` files from the source directory (`src/Coding Conventions, Best Practices/`) into `<workspace>/.conventions/`. Returns the list of relative paths (e.g., `.conventions/React.md`). Uses the `CONVENTIONS_SOURCE_DIR` constant (resolved to the source directory relative to `__dirname`).

4. **`deployAllConventionsToWorkspace(workspacePath: string): void`** — copies ALL convention files to the workspace. Called once during the development phase setup so all agents have access regardless of their specific languages.

5. **`getConventionReadInstructions(fileNames: string[]): string`** — returns a formatted prompt snippet that instructs the agent to read the specified files:
   ```
   <coding_conventions>
       BEFORE writing any code, you MUST read the following coding convention files
       using the read_file tool. These contain mandatory coding standards you must follow:
       - .conventions/Universal.md
       - .conventions/React.md
       - .conventions/TypeScript.md
       - .conventions/JavaScript.md
       Follow ALL rules in these files. They define naming conventions, code structure,
       error handling patterns, testing standards, and more for your technology stack.
       If you are making changes across multiple assignments, re-read the relevant
       convention file before starting each new assignment.
   </coding_conventions>
   ```

### Dependencies
- `fs`, `path` (Node built-ins)
- `TechDecision` type from `base-schemas`

### Estimated size
- ~120-150 lines

## Sub-Plan 2: Agent Prompt Modifications

**Goal**: Update all coding-agent prompts to include convention reading instructions. The instructions are generated dynamically based on the agent's languages and injected at prompt build time.

### Change 1: Developer Persona (`src/agents/_shared/persona.ts`)

**`buildDevPersona(cfg)`** — add a new parameter `conventionFiles?: string[]`. When provided, insert a `<coding_conventions>` block into the prompt (using `getConventionReadInstructions()`). Position it BEFORE `<workflow>` so agents read conventions before starting work.

Add to `DevPersonaConfig` interface:
```typescript
conventionFiles?: string[];
```

Insert the conventions block between `<critical_rules>` and `<workflow>`:
```
</critical_rules>

${conventionFiles ? getConventionReadInstructions(conventionFiles) : ''}

<workflow>
```

Also add to `<workflow>` step 2.5 (after reading architecture, before planning):
```
2.5. READ the coding convention files listed in <coding_conventions> using read_file.
     Apply these standards to ALL code you write.
```

### Change 2: Reviewer Persona (`src/agents/_shared/persona.ts`)

**`buildReviewerPersona(cfg)`** — same approach. Add `conventionFiles?: string[]` to config. Insert a `<coding_conventions>` block that tells reviewers:
```
<coding_conventions>
    Before reviewing, read the following convention files to understand the
    coding standards this project must follow:
    - .conventions/Universal.md
    - .conventions/TypeScript.md
    ...
    CHECK that the reviewed code follows these conventions. If it violates
    a convention rule, include it as a review comment with severity 'major'.
</coding_conventions>
```

### Change 3: QA Unit Prompt (`src/agents/qa/qa-unit.prompt.ts`)

Convert the static prompt string to a function `buildQaUnitPrompt(conventionFiles?: string[])` that optionally injects a conventions block. The QA unit agent writes test code, so it should follow testing conventions from the relevant language files.

### Change 4: QA E2E Prompt (`src/agents/qa/qa-e2e.prompt.ts`)

Same pattern — convert to a function with optional convention file injection.

### Change 5: DevOps Prompt (`src/agents/devops/devops.prompt.ts`)

Same pattern — DevOps writes CI/CD configs and Dockerfiles, so `Universal.md` plus relevant language conventions apply.

### Files Modified
- `src/agents/_shared/persona.ts` (2 functions + interface)
- `src/agents/qa/qa-unit.prompt.ts` (convert to function)
- `src/agents/qa/qa-e2e.prompt.ts` (convert to function)
- `src/agents/devops/devops.prompt.ts` (convert to function)

## Sub-Plan 4: Conductor Pipeline Integration

**Goal**: Deploy convention files to the workspace and pass resolved file lists through the pipeline to agent builders.

### Change 1: Development Node (`src/conductor/nodes.ts` — `developmentNode`)

Before calling `dispatchDevelopers()`:
1. Call `deployAllConventionsToWorkspace(state.workspacePath)` to copy all convention files
2. Pass `techStack: state.techStack` to `dispatchDevelopers()` so it can resolve per-agent conventions

Update `dispatchDevelopers()` signature to accept `techStack`.

### Change 2: Dispatcher (`src/agents/developers/dispatcher.ts`)

Update `dispatchDevelopers()` to:
1. Accept `techStack: TechDecision[]` parameter
2. Pass it through to `executePRWorkflow()` (add to `PRWorkflowInput`)

### Change 3: PR Workflow (`src/conductor/pr-workflow.ts`)

Update `executePRWorkflow()` to:
1. Accept `techStack` in `PRWorkflowInput`
2. For each dev agent invocation: call `resolveConventionFiles(entry.languages, techStack)` and pass the result to `buildDevAgent()`
3. For each reviewer agent invocation: call `resolveConventionFiles(entry.languages, techStack)` and pass to `buildReviewerAgent()`

### Change 4: QA Node (`src/conductor/nodes.ts` — `qaNode`)

Before creating QA agents:
1. Ensure conventions are deployed (idempotent — `deployAllConventionsToWorkspace` skips if already deployed)
2. Resolve convention files for QA agents based on tech stack
3. Pass to QA agent builders

### Change 5: DevOps Node (`src/conductor/nodes.ts` — `devopsNode`)

Same pattern:
1. Ensure conventions are deployed
2. Resolve convention files for DevOps (typically `Universal.md` + language-specific)
3. Pass to DevOps agent builder

### Files Modified
- `src/conductor/nodes.ts` (developmentNode, qaNode, devopsNode)
- `src/agents/developers/dispatcher.ts` (signature + passthrough)
- `src/conductor/pr-workflow.ts` (resolve conventions, pass to builders)

## Sub-Plan 5: Testing & Verification

**Goal**: Verify the integration works correctly.

### Test 1: Unit test for convention mapping (`tests/coding-conventions.test.ts`)

- Test `resolveConventionFiles()` with various agent language combinations
- Test that `Universal.md` is always included
- Test deduplication (e.g., React + TypeScript shouldn't list `JavaScript.md` twice)
- Test tech stack integration (e.g., tech stack choice 'Go' maps to `Go.md`)
- Test unknown languages return only `Universal.md`

### Test 2: Unit test for file deployment

- Test `deployConventionsToWorkspace()` copies files correctly
- Test idempotency (running twice doesn't fail)
- Test that the target directory (`.conventions/`) is created

### Test 3: Integration verification

- Run a dry test to verify:
  - Convention files are copied to workspace
  - Agent prompts include `<coding_conventions>` block
  - The file paths in the prompt match the deployed files

```bash
npx jest tests/coding-conventions.test.ts
npx tsc --noEmit  # Type check the whole project
```

## Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Agents ignore convention reading instructions | Place instruction in `<critical_rules>` with MUST language; add to workflow step 2.5 |
| Extra tool calls increase token cost | Reading 1-3 files = 1-3 extra tool calls out of 30-40 budget. Minimal impact. |
| Convention files too large (SCSS = 34KB) | Files are read on-demand, not injected into every prompt. Only relevant files are recommended. |
| Source convention directory missing at runtime | Resolve path relative to `__dirname` at build time; fail with clear error message |
| Reviewer agents skip convention checks | Explicit instruction in reviewer prompt: "CHECK code against these conventions" |
| Conventions conflict with architect's tech choices | Universal + language files don't prescribe tech choices, only coding style. No conflict expected. |
