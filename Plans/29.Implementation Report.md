## Summary

Added a `DEBUG_MODE` configuration flag (default `false`). When enabled:

1. **`logger.debug()` lines are printed** and written to `run.log`. Before this change they were always printed, at 16 call sites.
2. **A structured, redacted, time-ordered trace is written to `outputs/<run>/debug/`**, designed to be handed to an AI for root-cause analysis. It covers:
   - every LLM request and response — the exact request after history compaction, with messages de-duplicated;
   - every agent tool call, as the agent saw it;
   - every child process: git, shell, npm/test runners, docker, curl;
   - GitHub API calls and Docker (dockerode) operations;
   - graph node executions and routing decisions;
   - retries, crashes and every log line.

When `DEBUG_MODE=false`, every hook is a pass-through or identity wrapper and nothing extra is written.

The plan also included a prerequisite bug fix: **HITL sessions lost their `RunContext` after the first approval**. As a result, `run.log`, the ledger, full-responses, token tracking and the event bus silently fell back to uninitialised module defaults for the rest of a human-in-the-loop run.

## What a Debug Run Produces

```
outputs/<run>/debug/
├── README.md         # record schema, correlation keys, analysis workflow + ready-to-paste AI prompt
├── environment.json  # runtime, app version + git commit, run metadata, effective config (secrets masked)
├── trace.jsonl       # the complete chronological timeline — one JSON record per line
├── errors.jsonl      # every failure record, copied verbatim from trace.jsonl (same seq) — start here
└── summary.json      # counts/failures per kind, slowest ops, LLM stats per agent, command stats per program
```

**Record envelope** (every line): `{ seq, t, runId, kind, event, phase?, branch?, agentId?, ...fields }`

| kind | event(s) | Captures |
|------|----------|----------|
| `run` | `init`, `crash` | Session metadata (incl. app version, git commit, node version); crash context + full error |
| `node` | `start` / `end` / `error` | Graph node, state vitals on entry, update summary on exit, duration, stack |
| `route` | `decision` | Conditional edge `from` → `to` + the state vitals that drove it |
| `llm` | `start` / `end` / `error` | Exact request (de-duplicated messages, whitelisted params, tool names, full tool schemas once), response text / tool calls / thinking, usage incl. cache tokens, stop reason, served model, provider error status / body / request-id / retry-after |
| `tool` | `end` / `error` | Agent, tool, `toolCallId` (matches the LLM's `tool_calls[].id`), args, result exactly as the agent saw it, `ok`, loop-guard budget usage |
| `exec` | `start` (async) / `end` / `error` | Program, command / args, cwd, timeout, stdin, exit code, signal, `timedOut`, stdout / stderr (tail-weighted), duration, calling `file:line`; `probe: true` for expected non-zero exits |
| `http` | `end` / `error` | GitHub API (live Octokit or local stand-in): method, route, params, status, response summary |
| `docker` | `end` / `error` | Build / run / health / stop, incl. partial build logs on failure |
| `retry` | `attempt` / `giveup` | Label, attempt n/max, delay, transient flag, full error incl. cause chain |
| `event` | — | Event-bus `type` + `payload` |
| `ledger` | — | The same entry appended to `ledger.jsonl` |
| `response` | `logged` | Pointer to the `full-responses/` dump; `ok: false` when the agent produced no usable text |
| `log` | — | Every logger line (incl. DEBUG) and every tool-action line |
| `crash` | `uncaughtException` / `unhandledRejection` / `signal` | Process-level failures |

## Step 1: HITL `RunContext` Fix (`run.ts`)

### Problem
`runHumanInTheLoop()` and `continueRun()` create a `RunContext` and return a `RunSession` from inside `runWithContext(ctx, …)`. The session's `getState()` / `resume()` are called **later**, by the CLI readline loop (`cli/hitl-loop.ts`) and the REST handler (`POST /api/run/:id/approve` in `index.ts`), outside that `AsyncLocalStorage` scope.

Every per-run singleton (`_active()` pattern) therefore resolved to its module-level default after the first approval. Those defaults were never initialised for that run, so `run.log`, `ledger.jsonl`, `full-responses/`, the per-run token tracker, the event bus — and the new debug trace — silently stopped receiving data.

### Change
- `makeSession(conductor, threadId, sessionLog, ctx)` now takes the `RunContext` and returns
  `getState: () => runWithContext(ctx, getState)` and `resume: (d, f) => runWithContext(ctx, () => resume(d, f))`.
- Both callers (`runHumanInTheLoop`, the HITL path of `continueRun`) pass `ctx`.

### Test
`tests/run-session-context.test.ts` drives `runHumanInTheLoop()` with a fake conductor. It asserts that every `conductor.getState` / `updateState` / `invoke` call made from `session.getState()` and `session.resume('approve')` sees `getRunContext().id === session.threadId`, even though the test body itself runs outside any context.

## Step 3: Secret Redaction Module (`redact.ts`)

### Problem
1. **Import cycle:** `redactSecrets()` lived in `git-exec.ts`. The trace must redact everything it writes, but `git-exec` → `shell-exec` → `debug-trace` would have formed a cycle.
2. **Coverage gaps:**
   - the curl PR fallback sends `Authorization: token <PAT>` (the `token` scheme was not matched);
   - GitHub app / user / refresh tokens (`ghs_`, `ghu_`, `ghr_`) were not matched;
   - credentials embedded in URLs were not matched;
   - provider API keys were not matched.

### Changes
- `SECRET_PATTERNS` and `redactSecrets()` moved, unchanged for existing patterns, into the dependency-free `src/utils/redact.ts`. All consumers updated in the same change (Rule 29): `git-exec.ts`, `continue/singleton-rehydration.ts`, `tests/security-hardening.test.ts`.
- New patterns:
  - `\bgh[usr]_[A-Za-z0-9]{20,}` — length-bounded so identifiers like `laughs_count` are untouched;
  - `Authorization:\s*(?:Basic|Bearer|token)\s+\S+`;
  - URL userinfo `//user:pass@` → `//***REDACTED***@`;
  - `\bsk-[A-Za-z0-9_-]{20,}` (OpenAI / Anthropic);
  - `\bAIza[0-9A-Za-z_-]{35}\b` (Google).
- New `redactValues(text, values)`: exact-match scrub of configured secret values; values shorter than 8 characters are ignored.

The trace redacts with both. `redactValues` receives `GITHUB_TOKEN`, `GITHUB_PROJECT_TOKEN`, their base64 `x-access-token:<token>` forms (as sent in `http.extraHeader`), `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY` and `OAUTH_CLIENT_SECRET`.

## Step 5: Debug Trace Core (`debug-trace.ts`, `debug-environment.ts`, README template)

### Lifecycle
- **`initDebugTrace(outputPath, meta)`:**
  - creates `debug/` and writes `README.md` and `environment.json`;
  - flushes the records buffered before init (up to 2,000);
  - appends a `run`/`init` record;
  - returns the directory, or `null` when off.
  - On continue-run it appends a new session: `seq` restarts and `runId` changes.
- **`writeDebugSummary(opts?)`** writes `summary.json` from the in-memory stats and returns `{ file, records, failures }`. It never throws.

### Recording — `trace(record, opts?)`
- Adds the envelope (`seq`, `t`, `runId`, `kind`, `event`), then the ambient `withTraceContext` attribution (`phase`, `branch`, `agentId`), then the record's own fields; explicit fields win.
- **Serializer:** `JSON.stringify` with a replacer that **redacts every string first, then clips it**. Clipping keeps the head and tail around a `…[debug-trace: N chars elided of M]…` marker. It also handles `bigint`, serialized `Buffer`s (decoded to UTF-8), `Error` (→ `serializeError`), `Map`, `Set` and cycles. Redacting before clipping means a clip boundary can never expose part of a secret.
- **Record-size guard:** a record larger than 25 × the field cap is re-serialized with a tighter per-string cap (`cap / 10`, minimum 500) and marked `recordShrunk`, so its structure is preserved.
- **Failure routing to `errors.jsonl`:** a record is a failure when any of these hold:
  - `event: 'error'`;
  - `ok: false`;
  - `kind: 'crash'`;
  - `run`/`crash`;
  - `retry`/`giveup`;
  - a log line at level `ERROR`.

  Records tagged `probe: true` are never failures.
- Never throws. A write failure is reported once on stderr (`console.error`), because the logger cannot be imported.
- **Synchronous appends** (`fs.appendFileSync`, as in `run-ledger.ts`): records stay strictly ordered and survive `process.exit()` in the shutdown path.

### Context & wrappers
- `withTraceContext(patch, fn)` merges attribution into an `AsyncLocalStorage` store that is separate from `RunContext`. It is plain `fn()` when off.
- `traceSync(op, fn)` / `traceAsync(op, fn)` time an operation and write `end` / `error` records, plus a `start` record when `op.start` is set. They rethrow the **same** error object.
- `traceToolCall(agentId, tool, fn, getUsage)` — see Step 9.
- `traceOctokit(octokit, service)` — see Step 12.
- `serializeError(err)` keeps:
  - `name`, `message`, `code`, `status`, `statusCode`, `signal`, `type`, `errno`, `syscall`, `killed`, `requestID`;
  - the provider body (`err.error` → `body`) and Octokit `response.data`;
  - whitelisted headers (`request-id`, `retry-after`, `*ratelimit*`, `x-should-retry`, `cf-ray`; both `Headers` / `Map` and plain objects);
  - the stack;
  - the `cause` chain, up to depth 3. This unwraps LangChain `MiddlewareError` back to the provider error.
- `callerSite()` returns the `file:line` of the first stack frame outside `debug-trace` / `shell-exec` / `git-exec` / `node_modules` / `node:` internals.

### Process-level fallback
Signal and uncaught-exception handlers run outside any `RunContext`. Records written with `{ processLevel: true }` go to the most recently initialised run's trace.

### `environment.json` (`debug-environment.ts`)
- **Runtime:** Node version, platform, arch, pid, cwd, argv.
- **App:** `name` and `version` from `package.json`; git ref and commit read from `.git/HEAD`, loose refs or `packed-refs` (no subprocess, so it works in containers without git).
- **Run metadata.**
- **Config:** every exported value of `config.ts`, with keys ending in `_TOKEN`, `_SECRET`, `_API_KEY`, `_CLIENT_ID` or `PASSWORD` reduced to `***set***` / `''`. Module-interop keys (`default`, `__esModule`) are skipped. Raw `process.env` is never dumped (Rule 14).

### `README.md` (`templates/debug-trace-readme.template.ts`)
Documents:
- the files and the record envelope;
- every record kind and its fields;
- the LLM de-duplication scheme;
- redaction and clipping, stating the effective cap value;
- how the trace relates to `run.log`, `ledger.jsonl`, `full-responses/`, `state.json` and `run-diagnosis.md`;
- a 4-step analysis workflow;
- a **ready-to-paste prompt** for handing the folder to an AI.

## Step 7: Child-Process Tracing (`shell-exec.ts` + 15 call sites)

### Traced drop-ins

| Export | Replaces | Records |
|--------|----------|---------|
| `execSync(...)` | `child_process.execSync` | `exec` end / error |
| `execFileSync(...)` | `child_process.execFileSync` | `exec` end / error (+ `args`) |
| `execFileAsync(file, args, opts)` | `util.promisify(execFile)` | `exec` start + end / error |
| `execCapture(command, opts)` | `child_process.exec` callback pattern | `exec` start + end (`ok: exitCode === 0`); resolves, never rejects |

Properties:
- **Pass-through when off:** the original function is called with the exact received arguments (rest parameters, original arity).
- **Same results and errors when on:** same return value, same thrown error object.
- **Program name:** derived from the command and looks through `sh -c "<script>"` and `VAR=value` prefixes. For example `/bin/sh -c "npm test"` → `npm`.
- **Output:** stdout / stderr are redacted and clipped **tail-weighted** (20 % head / 80 % tail), because build and test failures print last. Exec errors record `exitCode` (`status` or numeric `code`), `signal`, `timedOut`, stdout, stderr and the first line of the message.
- **Probes:** `which …`, `command -v …` and any command with `--quiet` / `--verify` are tagged `probe: true`, so their expected non-zero exits stay out of `errors.jsonl`.
- **Lazy resolution:** `child_process` is resolved at call time — named imports compile to live property access, and `promisify` runs per call. Existing `jest.mock('child_process', () => ({ execSync }))` and `jest.spyOn(cp, 'exec')` tests keep working. Before this change, the module-level `promisify(execFile)` would have crashed under a mock that lacks `execFile`.

`defaultExec` / `defaultExecAsync` now use these drop-ins, so every quality-gate and security-gate step is traced: install, typecheck, build, lint, test, audit, `which` probes.

## Step 8: LLM Request/Response Tracing (`debug-llm-callback.ts`, `agent-factory.ts`)

### Design
- **A model-level LangChain callback, not a `wrapModelCall` middleware.** Model errors are rethrown inside middleware, and `MiddlewareError` keeps only `message` / `name` (with `cause`). An extra middleware layer would add another wrap. The callback receives the raw provider error, including status, body and headers.
- **`_awaitHandler: true`.** By default LangChain queues callback handlers in the background (a p-queue run under `asyncLocalStorageInstance.run(undefined, …)`). That would reorder LLM records relative to tool and command records and drop the run's `AsyncLocalStorage` context. Awaited handlers run inline. The handler also captures its `RunContext` at construction as a fallback.
- **One handler per agent instance**, created in `buildAgent()` only when `isDebugMode()`. It is added after `tokenCallback`, and `setInvocationId` forwards to both.

### Records
- **`handleChatModelStart`** → `llm`/`start`:
  - `llmRunId`, `agentId`, `model`, `phase`, `invocationId`;
  - `threadId` and `step` (from LangGraph metadata);
  - params from a whitelist of `invocation_params` — never credentials;
  - tool names on every call; full tool schemas the first time;
  - `messageCount`, `requestChars`;
  - `messages[]` reduced to `{ role, name, tool_call_id, tool_calls, content }`.
- **De-duplication:**
  - A message is recorded in full with a 12-character sha1 `hash` the first time this agent instance sends it. Afterwards it appears as `{ i, role, ref, chars }`.
  - The hash ignores Anthropic `cache_control` markers, which move every turn. A `cacheBreakpoint: true` flag shows where breakpoints are.
  - Binary blocks (`image`, `image_url`, `document`, audio, …) are replaced by `{ type, omittedChars }`.
  - Respawned agents start a fresh scope, so their first request is self-contained.
- **`handleLLMEnd`** → `llm`/`end`:
  - `durationMs`, `usage` (input / output / total / cache read / cache creation);
  - `stopReason` (`stop_reason` / `finish_reason`), `responseModel`, `responseId`;
  - `output { text, blocks, toolCalls, thinking }`.
- **`handleLLMError`** → `llm`/`error` with `serializeError(err)`.

### Shared usage extraction
The two-tier usage lookup (provider-level `llmOutput` first, then per-generation `usage_metadata`) moved from `token-callback.ts` into `token-usage-extractor.ts` as `usageFromLLMResult()`. Both callbacks use it, so there is no duplication (Rule 11) and token accounting is unchanged.

## Step 9: Tool-Call Tracing (`tool-loop-guard.ts`)

### Change
`tool(traceToolCall(agentId, originalTool.name, wrappedFn, usage), …)` — one line in `withLoopGuard()`. Every guarded tool of every agent is covered.

### Records
`tool` / `end`:
- `agentId`, `tool`, `toolCallId` (from `config.toolCall.id`), `args`;
- `result` exactly as the agent saw it, including `[CACHED …]`, `[BLOCKED]`, budget-pressure footers and terminal guidance;
- `resultChars`;
- `ok` — false when the result starts with `Error:` or `{"error"`;
- `usage` — the live loop-guard counters.

`tool` / `error` is written when the tool throws, and the error is rethrown unchanged. The call runs inside `withTraceContext({ agentId })`, so git / shell records produced by the tool carry the agent's id.

### Why not a `wrapToolCall` middleware
In `langchain@1.5.5`'s `ToolNode`, a registered `wrapToolCall` middleware makes tool exceptions travel through `#handleError(e, call, isMiddlewareError = true)`. With the default `handleToolErrors`, that path **re-raises** instead of converting the error to a ToolMessage, which would crash agents. Wrapping inside the loop guard preserves the existing semantics exactly.

## Step 10: Graph Node & Routing Tracing (`graph-trace.ts`, `graph.ts`, `dispatcher.ts`)

- **`traceNode(name, fn)`:**
  - runs the node inside `withTraceContext({ phase: name })` and records `node` `start` / `end` / `error`;
  - `vitals` on entry: phase, iteration, cancelled, `stopReason`, `pendingRerun`, resume phase, array counts, gate-passed, `e2eStatus`, acceptance, unrecoverable reason;
  - `update` on exit: per key, the array count plus up to 30 ids, the object keys, or the scalar value; also `nextPhase` and `durationMs`.
- **`traceRoute(from, router)`** records `route` / `decision` with `from`, `to` and vitals.
- **`graph.ts`:** all 13 nodes and all 11 conditional-edge routers are wrapped at registration. Exported routers (`afterQaRouter`, etc.) are unchanged for existing tests. Function arity is preserved.
- **`dispatcher.ts`:** the single `executePRWorkflow(...)` call runs inside `withTraceContext({ branch: branchName })`. Every git, gate, LLM and tool record of a branch workflow is attributed to its branch, including parallel dispatch.

Both wrappers return the original function when off.

## Step 12: GitHub API & Docker Tracing

### Octokit (`traceOctokit`)
- **Real Octokit:** `octokit.hook.wrap('request', …)` records method, route template (e.g. `/repos/{owner}/{repo}/pulls`), a whitelisted parameter set (`owner`, `repo`, `pull_number`, `head`, `base`, `title`, `body`, `merge_method`, …), status and a response summary (`number`, `state`, `merged`, `sha`, `html_url`, …). ## Deviations from the Plan

1. **`execAsync` → `execCapture`.** The plan proposed a promisified `exec`. `tests/shell-guards.test.ts` spies on `child_process.exec` with a plain callback mock that has no `util.promisify.custom`, which `promisify(exec)` would mishandle. `execCapture` keeps the callback API and resolves `{ stdout, stderr, exitCode }` with `runShell`'s exact mapping (`error?.code ?? (error ? 1 : 0)`).
2. **Off-mode tests live in their own file** (`tests/debug-mode-off.test.ts`). Jest's `isolateModules` + `doMock` cannot override a hoisted `jest.mock('../src/config')` in the same file: the main mock registry already holds the evaluated factory and is consulted before the isolated one.
3. **Added:**
   - the shared `tests/helpers/jsonl.ts`;
   - `docker` records for health checks and container stops;
   - `response` records flagged `ok: false` when an agent returned no usable text;
   - `isDebugMode()` guards around Docker build-log redaction;
   - skipping of module-interop keys in the config snapshot.
4. **Finalize summary** is called directly rather than inside its own `try/catch`: `writeDebugSummary()` already never throws.

## New Conventions (documented in `AI_Context.md`)

1. **Spawn child processes only through `shell-exec.ts`** (`execSync`, `execFileSync`, `execFileAsync`, `execCapture`) or `gitExec()` / `defaultExec()` / `defaultExecAsync()`. A direct `child_process` import is invisible to debug traces.
2. **`logger.debug()` is for debug mode only**; anything a normal run must show uses `info`.
3. **Deferred entry points must re-enter their run's `RunContext`** (`runWithContext(ctx, …)`), as `makeSession()` now does.
4. `debug-trace.ts` must not import `logger`, `artifact-writer` or `git-exec` (import cycle); redaction lives in the dependency-free `redact.ts`.

## Design Decisions

1. **Explicit chokepoints instead of global instrumentation.** Hooks sit at the 5 places every operation already passes through:
   - `buildAgent()` — every LLM call;
   - `withLoopGuard()` — every tool call;
   - `shell-exec.ts` — every child process;
   - `graph.ts` registration — every node and route;
   - `getOctokit()` — every GitHub call.

   Monkey-patching `child_process` or adding a top-level graph callback were rejected as too implicit and too noisy.
2. **Observe-only wrappers.** Every hook preserves arguments, return values and thrown-error identity. Two LangChain extension points (`wrapToolCall`, an extra `wrapModelCall` layer) were rejected specifically because they change error semantics.
3. **Redact before clip.** Clipping first could split a secret so that no pattern matches the visible half.
4. **De-duplicated, complete LLM capture.** Recording the full request per call would be roughly 100 MB+ per run. A summary would lose what the model actually saw. Hash references per agent instance keep the capture complete at a fraction of the size, and every respawn's first request is self-contained.
5. **One timeline plus a failure index.** Mirroring logs, events, ledger entries and response pointers into `trace.jsonl` means an AI can read one file in order. `errors.jsonl` (same `seq`) gives it an entry point.
6. **Synchronous appends.** This is a deliberate, documented exception to Rule 24, in debug mode only, matching `run-ledger.ts`. It guarantees ordering and that records survive `process.exit()` in the shutdown path.
7. **Probe tagging.** Expected non-zero exits (`which`, `git … --quiet`, `--verify`) are real but uninteresting. Tagging them keeps `errors.jsonl` focused without dropping them from the timeline.

## Risks & Considerations

1. **Disk usage.** Expect tens of MB per run with de-duplication. `DEBUG_TRACE_MAX_FIELD_CHARS` bounds each field, and complete agent conversations stay in `full-responses/`. Debug mode is meant for diagnosis runs, not always-on use.
2. **Sensitive content.** Credentials are redacted, but prompts, requirements, source code and tool output are captured by design. Treat `debug/` as confidential before sharing it with an external AI.
3. **Overhead.** Synchronous appends, a stack capture per command (`caller`) and per-string redaction add milliseconds per operation. That is negligible next to LLM latency, and zero when off.
4. **`_awaitHandler`** is a typed but underscore-prefixed `BaseCallbackHandlerInput` option. A test asserts `awaitHandlers === true`. If LangChain drops it, LLM records are still written (via the captured `RunContext`) but may lose strict ordering and `phase` / `branch` attribution.
5. **`debug-trace.ts` is 555 LOC**, close to the ~600 LOC limit (Rule 10). If it grows, split the GitHub helpers (`traceOctokit`, summarizers) into their own module.
6. **Concurrent server runs.** Process-level crash / signal records go to the most recently initialised run's trace.
7. **`caller` relies on source maps** (provided by `tsx` / `ts-jest`). In a compiled build without source maps it shows compiled paths.
8. **The tool `ok` flag is a heuristic** (`Error:` / `{"error"` prefix). The full result text is always recorded.
9. **Continue-run sessions restart `seq`.** Order by file position or `t`, and distinguish sessions by `runId` and the `run`/`init` record.
