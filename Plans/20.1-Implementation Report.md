**Status**: Completed

---

### Summary

Implemented automatic LLM provider detection and model creation so that setting any agent model to a Claude or Gemini model name automatically routes to the correct LangChain chat model class (`ChatAnthropic` or `ChatGoogleGenerativeAI`), while all existing OpenAI-compatible models continue working unchanged.

New config exports:
| Variable | Type | Default | Purpose |
|----------|------|---------|---------|
| `ANTHROPIC_API_KEY` | `string` | `''` | API key for Anthropic (Claude) models |
| `GOOGLE_API_KEY` | `string` | `''` | API key for Google (Gemini) models |
| `ANTHROPIC_BASE_URL` | `string` | `''` | Optional base URL override for Anthropic (proxy support) |
| `GOOGLE_BASE_URL` | `string` | `''` | Optional base URL override for Google (proxy support) |
| `LLM_PROVIDER_DETECTION` | `'auto' \| 'openai'` | `'auto'` | Provider detection strategy; `'openai'` forces all models through the OpenAI-compatible endpoint |

#### 2. `src/agents/_shared/llm-provider.ts` (NEW)
**Change**: Created the multi-provider LLM factory module.

Exports:
- `type LLMProvider = 'openai' | 'anthropic' | 'google'`
- `interface CreateModelOpts` — options for model creation (model name, temperature, maxTokens, timeout, callbacks, plus OpenAI-specific: apiKey, baseURL, customFetch, jsonMode)
- `detectProvider(modelName: string): LLMProvider` — pattern matching:
  - `LLM_PROVIDER_DETECTION === 'openai'` -> always returns `'openai'` (escape hatch)
  - `/claude|anthropic/i` -> `'anthropic'`
  - `/gemini/i` -> `'google'`
  - Everything else -> `'openai'` (covers `gpt-*`, `o1-*`, `llama-*`, `mistral-*`, `gemma-*`, etc.)
- `createChatModel(opts: CreateModelOpts): BaseChatModel` — creates the right LangChain model:
  - **OpenAI**: `ChatOpenAI` with OAuth fetch chain, `LLM_BASE_URL`, JSON mode support
  - **Anthropic**: `ChatAnthropic` with `ANTHROPIC_API_KEY`, optional `ANTHROPIC_BASE_URL` via `clientOptions`
  - **Google**: `ChatGoogleGenerativeAI` with `GOOGLE_API_KEY`, optional `GOOGLE_BASE_URL` via `baseUrl`
  - All providers: `maxRetries: 0` (retries handled centrally)

Includes warning logs when an API key is missing for the detected provider.

#### 3. `src/agents/_shared/agent-factory.ts`
**Change**: Refactored `buildAgent()` to use `createChatModel()` instead of inline `new ChatOpenAI(...)`.

Key changes:
- Removed direct `ChatOpenAI` import (no longer needed)
- Added imports: `createChatModel`, `detectProvider` from `./llm-provider`
- Provider detection happens early to determine:
  - Whether to set up the OAuth fetch chain (OpenAI only)
  - Whether JSON mode is applicable (OpenAI only — `response_format` not supported by Anthropic/Google)
- The OAuth fetch chain (`oauthFetch` -> `cassetteFetch` -> `throttledFetch`) is only constructed when `provider === 'openai'`
- Debug logging when a non-OpenAI provider is used
- **Function signature unchanged** — all callers continue to work without modification
- `createReactAgent()` accepts any `BaseChatModel`, so no downstream changes needed

#### 4. `.env.example`
**Change**: Added a `Multi-Provider LLM (Sub-Plan 20)` section with documentation for all new environment variables, inserted between the Per-Agent Models section and the OAuth2 section.

#### 5. `AI_Context.md`
**Changes**:
- **Technology Stack table**: Updated Agent Framework row to include `ChatAnthropic` and `ChatGoogleGenerativeAI` alongside `ChatOpenAI`
- **Directory Structure**: Added `llm-provider.ts` entry under `agents/_shared/`
- **Agent Factory Pattern section**: Expanded from 4 steps to 5 steps, documenting provider detection, the three provider paths, and the escape hatch (`LLM_PROVIDER_DETECTION=openai`)

---

### Design Decisions

1. **Auto-detect from model name** — No per-agent `_PROVIDER` env vars. Setting `ARCHITECT_MODEL=claude-sonnet-4-20250514` automatically routes to `ChatAnthropic`.
2. **OpenAI is the fallback** — Any model name that doesn't match Anthropic/Google patterns goes through `ChatOpenAI`, preserving backward compatibility for all existing models.
3. **Direct API keys** — Anthropic uses `ANTHROPIC_API_KEY`, Google uses `GOOGLE_API_KEY`. No proxy/OAuth for these providers.
4. **OAuth/throttle/cassette only for OpenAI** — The custom fetch chain remains OpenAI-specific. Anthropic/Google rely on `retryWithBackoff` at the invocation level.
5. **JSON mode only for OpenAI** — `response_format: { type: 'json_object' }` is OpenAI-specific. The JSON schema instruction in the prompt (which all providers receive) is the primary mechanism for structured output.
6. **Escape hatch** — `LLM_PROVIDER_DETECTION=openai` forces all models through `ChatOpenAI`, useful for running Anthropic/Google models through an OpenAI-compatible proxy.

## Sub-Plan 2: Strong Model PR Fixer

**Status**: Completed  
**Date**: 2026-08-15

---

### Summary

Implemented a "strong model fixer" agent that takes over PRs that exhaust their review iterations. When a PR remains open after the regular review loop (and optionally the existing rank-based escalation), a dedicated powerful model receives comprehensive context — the original task, ALL review comments from every iteration, the full diff, quality gate results, and integrity findings — and does a single-pass fix attempt followed by a final review.

---

### Files Modified

#### 1. `src/config.ts`
**Change**: Added new environment variables in a new `Strong Model PR Fixer (Sub-Plan 20)` section (inserted between the Review & Merge Policy section and Agent Budgets & Context section).

New config exports:
| Variable | Type | Default | Purpose |
|----------|------|---------|---------|
| `STRONG_FIXER_MODEL` | `string` | `''` | Model for the strong fixer agent (e.g. `claude-opus-4.6`). Empty falls back to `PRINCIPAL_DEV_MODEL` |
| `STRONG_FIXER_ENABLED` | `boolean` | `true` | Enable/disable the strong fixer |
| `STRONG_FIXER_MAX_TOOL_CALLS` | `number` | `40` | Max tool calls for the strong fixer agent |
| `PR_EXHAUSTION_STRATEGY` | `'escalate-then-fix' \| 'fix-only' \| 'escalate-only'` | `'escalate-then-fix'` | Controls which recovery steps run when max review iterations are reached |

#### 2. `src/agents/developers/dev-agent.builder.ts`
**Change**: Added `buildStrongFixerAgent()` function.

New export:
- `buildStrongFixerAgent(apiKey, workspaceRoot, gitContext?, baseBranch?, conventionFiles?, isMaintainMode?)` — Creates a dev agent with:
  - **Model**: `STRONG_FIXER_MODEL` or fallback to `PRINCIPAL_DEV_MODEL` (auto-routed via Sub-Plan 1's multi-provider abstraction)
  - **Persona**: `principal` rank, `fullstack` domain, broad language support (`typescript`, `javascript`, `python`, `java`, `go`)
  - **Tools**: Same as regular dev agents (workspace + shell, optionally git)
  - **Tool budget**: `STRONG_FIXER_MAX_TOOL_CALLS` (default 40, higher than regular dev agents)
  - **Temperature**: 0.2 (slightly lower for precise fixes)
  - **ID**: `'strong-fixer'`

Added imports for `STRONG_FIXER_MODEL` and `STRONG_FIXER_MAX_TOOL_CALLS` from config.

#### 3. `src/conductor/pr-workflow.ts`
**Change**: Refactored escalation (section 3b) and added the strong fixer step (section 3c).

Key changes:

**Section 3b (Escalation check) — now guarded by `PR_EXHAUSTION_STRATEGY`:**
- Added `PR_EXHAUSTION_STRATEGY !== 'fix-only'` guard to the existing escalation block
- When `PR_EXHAUSTION_STRATEGY` is `'fix-only'`, escalation is skipped entirely
- The existing escalation logic is unchanged — only the outer guard is added

**Section 3c (Strong Model Fixer) — new section added after escalation:**
- **Trigger condition**: `STRONG_FIXER_ENABLED` AND `PR_EXHAUSTION_STRATEGY !== 'escalate-only'` AND `prStatus === 'open'`
- **Budget check**: Verifies `getEffectiveLimits().maxReviewIterations > 0` before running
- **Context assembly**: Collects ALL review comments from all iterations (`allReviews.flatMap(r => r.comments)`), current full diff (truncated at 30K chars), quality gate results, integrity findings
- **Agent invocation**: `buildStrongFixerAgent()` via `invokeDevAgent()` with respawn support
- **Post-fix quality gates**: Runs `runQualityGates()` after the fixer's changes
- **Final review**: Uses `selectEscalationCandidate()` to find a reviewer, invokes a reviewer agent, records the review
- **PR comment**: Posts the final review as a GitHub issue comment
- **Durable commit**: Wrapped in `try/finally` with `commitWorktree()` to preserve partial work
- **Event**: Emits `'pr:strong-fixer'` run event

Added imports:
- `buildStrongFixerAgent` from `../agents/developers/dev-agent.builder`
- `STRONG_FIXER_MODEL`, `STRONG_FIXER_ENABLED`, `STRONG_FIXER_MAX_TOOL_CALLS`, `PR_EXHAUSTION_STRATEGY` from `../config`

#### 5. `.env.example`
**Change**: Added a `Strong Model PR Fixer (Sub-Plan 20)` section with documentation for all new environment variables, inserted between the Review & Merge Policy section and Agent Budgets & Context section.

**Changes**:

- Renumbered subsequent steps (11-14)

---

### Design Decisions

1. **Configurable strategy (`PR_EXHAUSTION_STRATEGY`)** — Three modes allow full control:
   - `'escalate-then-fix'` (default): Run existing rank-based escalation first. If still unresolved, run the strong fixer.
   - `'fix-only'`: Skip rank-based escalation entirely. Go straight to the strong fixer.
   - `'escalate-only'`: Keep existing behaviour only. No strong fixer (backward-compatible).
2. **Comprehensive context** — Unlike the regular fix step (which only gets the latest reviewer's comments), the strong fixer gets ALL comments from all iterations, the full diff, quality gate results, integrity findings, and the original task.
3. **Uses configurable model** — `STRONG_FIXER_MODEL` can be set to any model (e.g. `claude-opus-4.6`). Combined with Sub-Plan 1, this automatically uses the right provider.
4. **Budget-aware** — The strong fixer respects the run budget. If the budget is exhausted (`getEffectiveLimits().maxReviewIterations <= 0`), it won't run.
5. **Single pass** — The fixer gets one attempt. It doesn't enter a new review loop — it does one fix pass, one quality gate run, and one review. This prevents infinite cost spirals.
6. **Durable commits** — Follows the established Sub-Plan 06 pattern: `try/finally` with `commitWorktree()` to preserve partial work even if the fixer throws.
7. **`escalated_open` removed from condition** — The plan mentioned `prStatus === 'escalated_open'` as a trigger, but the actual code flow never sets this status. TypeScript's type narrowing confirmed this — the condition was simplified to `prStatus === 'open'`.

### Risks Mitigated

- **Cost**: Strong models are expensive. Mitigated by: (1) run budget (`MAX_RUN_COST_USD`) caps total spend, (2) single pass — no looping, (3) configurable via `STRONG_FIXER_ENABLED=false`
- **Context size**: Full diff + all comments could exceed context windows. Mitigated by: diff truncated at 30K chars, PR body capped at 3K chars
- **Infinite cost spiral**: Fixer produces poor code? Won't loop — one attempt, one review, done

### Design Decisions

2. **Constructor mocking** — LangChain model constructors are mocked to verify correct class selection and configuration passthrough without requiring actual API keys or network calls.
3. **Config-per-test pattern** — Uses `jest.resetModules()` + `require()` (not static imports) to allow each test to set different config values, following the established pattern in `tests/run-budget.test.ts`.
4. **Pricing based on public API pricing** — Model pricing uses current published API rates. The `MODEL_PRICING_OVERRIDES` env var allows runtime adjustments without code changes.
5. **No changes to cost.ts** — The cost estimation functions are data-driven via `MODEL_PRICING`. Adding pricing entries to config.ts is sufficient; the utility code works unchanged.
