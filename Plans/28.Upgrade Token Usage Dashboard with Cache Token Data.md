# Upgrade Token Usage Dashboard with Cache Token Data

Enhance the Angular dashboard and HTML token report to surface cache token data (cache reads, cache creations, cache hit rate, cache savings) in tables and charts, and add cache-aware pricing to the cost estimates throughout.

---

## Current State Analysis

### What exists today

**Angular Dashboard (`run-session.component`)**:
- The "obs-bar" shows only: LLM Calls, Tokens (total), Budget level
- The completion stats section shows: Epics, Stories, Tasks, File Changes, PRs, Test Reports, Bugs, LLM Calls
- No cache token data displayed at all
- No charts/graphs of any kind (no charting library in the Angular project)
- WebSocket `tokens:update` event currently sends: `totalCalls`, `totalTokens`, `totalInputTokens`, `totalOutputTokens` -- no cache fields

**HTML Token Report (`token-report.ts`)**:
- Summary cards: Total Tokens, Input Tokens, Output Tokens, LLM Calls, Cache Hit Rate, Cached Input Tokens, I/O Ratio, Agents, Estimated Cost
- Charts (Chart.js): Pie (tokens by agent), Bar (input/output by agent), Bar (tokens by phase), Bar (cost by agent)
- Tables: Cost by Agent (no cache columns), Usage by Phase (no cache columns), Usage by Model (no cache columns), Invocation Efficiency, Billed vs List Cost (shows cache savings), All Invocations detail (no cache columns)
- Cache savings section only appears when `cacheSavings > 0.001`

**Data available**: `TokenCallRecord` already has `cacheReadTokens` and `cacheCreationTokens` (optional). `RunUsageSummary` has `totalCacheReadTokens`, `totalCacheCreationTokens`, `cacheHitRate`. The `estimateCost()` function already handles cache-aware pricing with configurable multipliers.

**Pricing**: `ModelPricingEntry` already supports `cacheReadMultiplier` (default 0.1) and `cacheWriteMultiplier` (default 1.25). Cost estimation is already cache-aware. However, the per-model pricing table in the HTML report only shows `inputPer1k` and `outputPer1k` -- it doesn't show the cache read/write rates.

## Implementation Plan

### 1. Enhance the WebSocket `tokens:update` event payload

**File**: `src/utils/token-tracker.ts` (lines 190-198)

Add cache token fields to the `tokens:update` event emission:
- `totalCacheReadTokens`
- `totalCacheCreationTokens`
- `cacheHitRate`
- `estimatedCost` (add cache-aware cost to the event)

### 2. Enhance the Angular dashboard `run-session` component

**Files**: 
- `dashboard/src/app/pages/run-session/run-session.component.ts`
- `dashboard/src/app/pages/run-session/run-session.component.html`
- `dashboard/src/app/pages/run-session/run-session.component.scss`

#### 2a. Add new tracked fields to the component
- `totalInputTokens`, `totalOutputTokens` (already in WS event, not consumed)
- `totalCacheReadTokens`, `totalCacheCreationTokens`, `cacheHitRate`
- `estimatedCost`
- Populate from both: (a) initial `state.tokenUsage` array on `refreshState()`, and (b) live `tokens:update` WS events

#### 2b. Enhance the observability bar
Replace the current minimal obs-bar with a richer token dashboard section showing:
- Total Tokens (existing)
- Input / Output tokens
- Cache Read Tokens + Cache Creation Tokens
- Cache Hit Rate (percentage)
- Estimated Cost (cache-aware)
- LLM Calls (existing)

#### 2c. Add inline charts using Chart.js (direct, no Angular wrapper)
Install `chart.js` as a dependency in the dashboard project. Create a dedicated `TokenUsageChartComponent` (standalone Angular component) that uses Chart.js directly via canvas refs:
1. **Doughnut chart**: Token distribution (Input vs Output vs Cache Read)
2. **Bar chart**: Cache efficiency -- cache read tokens vs uncached input tokens vs cache write tokens
3. These update live via the WS events
4. Chart instances managed manually with `ngAfterViewInit`/`ngOnDestroy` lifecycle

#### 2d. Enhance the completion stats section
Add: Total Tokens, Cache Hit Rate, Estimated Cost to the completion card.

### 3. Enhance the HTML token report tables with cache columns

**File**: `src/utils/token-report.ts`

#### 3a. Cost Breakdown by Agent table
Add columns: `Cache Read`, `Cache Write`, `Cache Cost` (showing the discounted cost for cached tokens)

#### 3b. Usage by Phase table
Add columns: `Cache Read`, `Cache Write`

#### 3c. Usage by Model table
Add columns: `Cache Read`, `Cache Write`

#### 3d. All Invocations detail table
Add columns: `Cache Read`, `Cache Write`

#### 3e. Pricing Rates table
Add columns: `Cache Read ($/1K)`, `Cache Write ($/1K)` showing the effective per-1K rates after applying multipliers.

### 4. Enhance the HTML token report charts

**File**: `src/utils/token-report.ts`

#### 4a. Input vs Output bar chart -- add cache breakdown
Change the stacked bar chart from 2 datasets (Input, Output) to 4 datasets:
- Cache Read Tokens (discounted input)
- Cache Write Tokens (surcharged input) 
- Uncached Input Tokens
- Output Tokens

#### 4b. Add a new "Cache Efficiency by Agent" chart
A horizontal bar chart showing each agent's cache hit rate (% of input tokens that were cache reads).

#### 4c. Cost chart -- add cache cost breakdown
Change from Input Cost / Output Cost to: Cache Read Cost / Cache Write Cost / Uncached Input Cost / Output Cost

### 5. Enhance RunUsageSummary aggregation to include per-agent cache data

**File**: `src/utils/token-tracker.ts`

Add `cacheReadTokens` and `cacheCreationTokens` to `AgentUsageSummary` so each agent row can show its own cache data (currently only available at the run level).

Similarly add to the `byPhase` and `byModel` aggregations.

### 6. Update the `estimateCostLocal` in token-report.ts

**File**: `src/utils/token-report.ts`

The local `estimateCostLocal()` function currently ignores cache tokens. Update it to use the shared `estimateCost()` from `cost.ts` instead (with cache parameters), eliminating the duplication.

### 7. Tests

**Files**:
- Update `tests/cost.test.ts` if any API changes
- Add tests for the new `AgentUsageSummary` cache fields in `token-tracker`
- Verify the chart data generation logic in token-report

## Risks / Considerations

- **No breaking changes**: All new `TokenCallRecord` fields are optional; `AgentUsageSummary` additions are backward-compatible
- **Chart.js version**: Pin to a stable version (4.4.x, same as the HTML report CDN)
- **Performance**: Chart rendering in the Angular dashboard should be efficient; use `OnPush` change detection and only re-render charts when data actually changes
- **Existing conventions**: Follow the existing dark theme design language (Tokyo Night inspired colors), use the same CSS variable system
