# DEBUG_MODE: verbose, AI-ready run tracing

Add a `DEBUG_MODE` env flag. When it is on, `logger.debug()` lines are printed and a structured, redacted, time-ordered trace is written to `outputs/<run>/debug/`: every LLM request and response, agent tool call, git/shell/docker/GitHub operation, graph node and routing decision. When it is off, nothing changes.

## Decisions (confirmed with you)
- **Output:** a structured `outputs/<run>/debug/` folder. DEBUG lines also go to `run.log`.
- **`logger.debug()`:** only prints when `DEBUG_MODE=true`. Today it always prints, at 16 call sites.
- **LLM capture:** full but de-duplicated. Every call records the exact request the model received after history compaction. A message is stored in full the first time it appears; later repeats become short hash references.
- **HITL bug:** fixed in this change (step 1).
- **How to turn it on:** `.env` only, per Rule 6. A per-run toggle in the CLI or dashboard is a follow-up.

## What a debug run produces
```
outputs/<run>/debug/
├── README.md         # file layout, record schema, how records link up, AI analysis guide + ready-to-paste prompt
├── environment.json  # node/platform, app version + git commit (read via fs), run meta, effective config (secrets masked)
├── trace.jsonl       # ONE time-ordered timeline, one JSON record per line
├── errors.jsonl      # every failure record (same seq as trace.jsonl). Start here.
└── summary.json      # counts, failures, slowest ops, per-agent LLM stats, per-program exec stats
```
Every record starts with the same fields: `{ seq, t, runId, kind, event, phase?, branch?, agentId?, ... }`.

| kind | events | captures |
|---|---|---|
| `run` | init, crash | run meta; crash context with full error and stack |
| `node` | start / end / error | graph node; state summary (phase, iteration, item counts) on entry; summary of the state update it returns; duration; stack |
| `route` | decision | conditional edge from → to, plus the state summary (why it routed there) |
| `llm` | start / end / error | exact request after compaction (de-duplicated messages, params, tool names; full tool schemas once), response text / tool_calls / thinking, usage incl. cache, stop reason, served model, duration; provider error status / body / request-id / retry-after |
| `tool` | end / error | agentId, tool, toolCallId (matches the LLM's tool_calls), args, result exactly as the agent saw it (incl. `[CACHED]` / `[BLOCKED]` / budget markers), loop-guard budget usage, duration |
| `exec` | start (async only) / end / error | program, command/args, cwd, timeout, stdin, exit code, signal, stdout, stderr, duration, calling `file:line` |
| `http` | end / error | GitHub API (live Octokit or the local stand-in): method, route, status, short request/response summary |
| `docker` | end / error | build / run / health / stop, incl. partial build logs on failure |
| `retry` | attempt / giveup | label, attempt n/max, delay, full error incl. cause chain |
| `event` / `ledger` / `response` | — | copies of event-bus events, ledger entries, and full-response dump pointers (filename to open) |
| `log` | level | every logger line (incl. DEBUG) and tool-action line |
| `crash` | uncaughtException / unhandledRejection / signal | process-level failures |

**Fields that link records together:** `seq`, `runId`, `phase`, `branch`, `agentId`, `invocationId` (matches `token-usage.json` and `full-responses/`), `llmRunId`, `toolCallId`.

## Design principles
- **Debug off = exactly today's behaviour.** Every hook is a pass-through or identity wrapper, and no files are written. Config is read lazily and `undefined` counts as off, so tests with partial `jest.mock('../src/config')` mocks keep working.
- **Debug on = observe only.** Same arguments, same return values, and the *same* thrown error objects.
- **Rejected approaches:**
  - A LangChain `wrapToolCall` middleware: LangChain's ToolNode would then re-raise tool exceptions instead of turning them into ToolMessages, which changes behaviour.
  - An extra `wrapModelCall` layer: it adds another `MiddlewareError` wrapping around model errors.
  - Global monkey-patching of `child_process`.
- **Scoped per run** via `RunContext` and the existing `_active()` pattern (Rule 22). Records written before intake are held in a bounded memory buffer and flushed at init. Process-level crash records fall back to the most recently initialised run.
- **Writes are synchronous** (`appendFileSync`), the same as `run-ledger.ts`, so ordering is exact and nothing is lost on a crash. This only happens in debug mode.
- **One JSON serializer** applies clipping and redaction to every string:
  - head/tail clip with an explicit `…[N chars elided of M]…` marker;
  - exec output is clipped tail-heavy, because failures print last;
  - redaction = secret patterns + exact configured secret values + base64 `x-access-token` auth headers.
- **No import cycles.** `debug-trace.ts` imports only `config`, `run-context`, `redact`, `debug-environment` and the template. It never imports `logger`, `artifact-writer` or `git-exec`, because those all import it (directly or indirectly).

## Implementation steps

### 1. Prerequisite fix — HITL runs lose their RunContext (`src/conductor/run.ts`)
- **Bug:** `session.resume()` is called from `cli/hitl-loop.ts` and `index.ts` *outside* `runWithContext`. After the first approval, run.log, the ledger, full-responses, token tracking and the event bus silently fall back to uninitialised module defaults.
- **Fix:** `makeSession(conductor, threadId, sessionLog, ctx)` wraps `getState()` and `resume()` in `runWithContext(ctx, …)`. Pass `ctx` from `runHumanInTheLoop` and the HITL path of `continueRun`.

### 2. Config (`src/config.ts`, new "Debug Mode" section)
- `DEBUG_MODE = envBool('DEBUG_MODE', false)`
- `DEBUG_TRACE_MAX_FIELD_CHARS = envInt('DEBUG_TRACE_MAX_FIELD_CHARS', 20000)` — maximum size of any single string field; 0 = unlimited; clamped at ≥ 0.

### 3. Redaction module (new `src/utils/redact.ts`)
- Move `SECRET_PATTERNS` and `redactSecrets()` out of `git-exec.ts` (needed to avoid an import cycle).
- Extend the patterns:
  - `gh[pousr]_…` — a superset of the existing `ghp_` / `gho_` patterns;
  - `Authorization: token …` — the curl PR fallback uses this scheme;
  - URL credentials (`//user:pass@`);
  - `sk-…` / `sk-ant-…` / `AIza…` API keys.
- Add `redactValues(text, values)` for exact-match scrubbing (ignores values shorter than 8 characters).
- Update every consumer in the same change (Rule 29): `git-exec.ts`, `continue/singleton-rehydration.ts`, `tests/security-hardening.test.ts`.

### 4. Per-run state (`src/utils/run-context.ts`)
- Add a `DebugTraceState` class holding: dir, seq, the bounded pre-init buffer, and stats counters.
- Add `readonly debugTrace` to `RunContext`.

### 5. Debug trace core
- **New `src/utils/debug-trace.ts` (~380 LOC):**
  - `isDebugMode()`, `initDebugTrace(outputPath, meta)` (returns the dir, or null when off), `trace(record)` (never throws; one-time `console.error` if a write fails);
  - `withTraceContext(patch, fn)`: an `AsyncLocalStorage` scope that adds phase / branch / agentId to records; plain `fn()` when off;
  - `traceSyncOp` / `traceAsyncOp`, `traceToolCall`, `traceOctokit`, `serializeError` (status, code, provider body, whitelisted request-id / retry-after / rate-limit headers, cause chain up to depth 3), `callerSite`;
  - `writeDebugSummary()`, `_resetDebugTrace()`;
  - failure routing to `errors.jsonl`: `event:'error'`, `ok:false`, log level ERROR, and crashes. Expected non-zero probe commands (`which …`, `git … --quiet`, `--verify`) are tagged `probe:true` and kept out of `errors.jsonl`.
- **New `src/utils/debug-environment.ts` (~70 LOC):** `buildDebugEnvironment(meta)`. Reads config exports and masks keys ending in `_TOKEN`, `_SECRET`, `_API_KEY`, `_CLIENT_ID` or `PASSWORD`. Never dumps `process.env` (Rule 14). Reads the app version and git HEAD with `fs`, so no subprocess is spawned.
- **New `src/templates/debug-trace-readme.template.ts`:** `renderDebugTraceReadme()`. Contents: schema, how records link up, redaction and clipping notes, how the trace relates to `run.log` / `ledger.jsonl` / `full-responses/` / `state.json` / `run-diagnosis.md`, and a suggested analysis workflow plus a ready-to-paste prompt.

### 6. Logger (`src/utils/logger.ts`)
- `debug()` prints only when `DEBUG_MODE` is on.
- `log()` and `logToolAction()` also copy each line into the trace via `traceLog(level, tag, msg)`.
- The public API is unchanged, so the manual mock in `__mocks__/logger.ts` still fits.

### 7. Child processes (`src/utils/shell-exec.ts` — the canonical child-process utility per Rule 11)
- Add traced drop-in replacements with the same signatures: `execSync`, `execFileSync`, `execFileAsync` (returns `{stdout, stderr}`), `execAsync`.
  - They look up the `child_process` functions at call time, so existing `jest.mock('child_process')` tests still work.
  - `promisify` becomes lazy (it currently runs at module load and would crash when a mock has no `execFile`).
  - The async versions also write a `start` record.
- `defaultExec` / `defaultExecAsync` use the traced versions, which covers every gate step (install / typecheck / build / lint / test / audit).
- Move each direct `child_process` user onto the drop-ins (mostly a one-line import change):
  - `utils/git-exec.ts` (covers all `gitExec` / `gitExecVerbose` / `gitPush` calls), `utils/github-local.ts`, `utils/github-repo-manager.ts`;
  - `tools/mcp/playwright-preflight.ts`, `conductor/pr/pr-github.ts` (curl fallback);
  - `conductor/nodes/intake.ts`, `conductor/nodes/qa.ts`, `conductor/nodes/_git-helpers.ts` (also drop its local `promisify`);
  - `conductor/workspace-snapshot.ts`, `conductor/test-runner.ts` (drop its local `promisify`);
  - `conductor/run-invariants.ts` (replace the inline `require('child_process')`);
  - `conductor/merge-resolve.ts`, `conductor/devops-verify.ts`, `conductor/agent-respawn.ts`;
  - `tools/shell/shell-tools.ts`: `runShell` switches to `execAsync`, keeping the same exitCode / stdout / stderr mapping.

### 8. LLM requests and responses
- **New `src/utils/debug-llm-callback.ts` — `DebugTraceCallbackHandler`:**
  - Created with `_awaitHandler: true`. LangChain queues callbacks in the background by default, which would lose ordering and the run's `AsyncLocalStorage` context. It also keeps the `RunContext` captured at construction as a fallback.
  - `handleChatModelStart`: messages are reduced to `{role, name, tool_call_id, tool_calls, content}` and de-duplicated by a 12-character sha1 per agent instance (each respawn starts fresh). Params come from a whitelist of `invocation_params`. Also records `thread_id` / `langgraph_step` from metadata.
  - `handleLLMEnd` and `handleLLMError` as described in the table above.
- **`agents/_shared/agent-factory.ts`:** create the handler only in debug mode; `callbacks: [tokenCallback, debugCallback?]`; `setInvocationId` forwards to both.
- **No duplicated usage parsing:** move the two-step usage lookup from `token-callback.ts` into `token-usage-extractor.ts` as `usageFromLLMResult()`, used by both callbacks. No behaviour change.

### 9. Agent tool calls (`agents/_shared/tool-loop-guard.ts`, +3 lines)
- In debug mode, wrap each guarded tool function with `traceToolCall(agentId, toolName, wrappedFn, () => usage())`.
- It runs inside `withTraceContext({agentId})`, so the git/shell records produced inside the tool carry the agent's id.
- It reads `toolCallId` from `config.toolCall?.id`, and rethrows errors unchanged.

### 10. Graph nodes and routing
- **New `src/conductor/graph-trace.ts`:**
  - `traceNode(name, fn)`: runs the node inside `withTraceContext({phase})` and records start / end / error, with the state summary in and a summary of the returned update out;
  - `traceRoute(from, router)`: records each routing decision.
  - Both return the original function unchanged when debug is off.
- **`conductor/graph.ts`:** wrap all 13 `addNode` functions and all 9 router functions at registration. The exported routers stay unchanged for existing tests.
- **`agents/developers/dispatcher.ts`:** wrap the single `executePRWorkflow(...)` call in `withTraceContext({ branch: branchName }, …)`.

### 11. Copies of existing observability into the trace (one line each)
- `utils/event-bus.ts` `emitRunEvent()`, `utils/run-ledger.ts` `appendLedger()`, `utils/response-log.ts` `logAgentResponse()` (records the dump filename).
- `utils/retry.ts`: a record per retry attempt and a final give-up record.

### 12. GitHub API and Docker
- **Octokit:** `pr/pr-github.ts` `getOctokit()` (both live and local mode) and both `new Octokit` sites in `utils/github-repo-manager.ts` go through `traceOctokit()`.
  - Live mode uses `octokit.hook.wrap('request')`.
  - The local stand-in, which has no hooks, is wrapped in a Proxy that records each `namespace.method(params)` call.
- **`executor/docker-runner.ts`:** records for build / run / health / stop.
  - Move the `chunks` variable out of the inner promise so partial build logs can be recorded when a build fails.
  - Records env var *names* only, never values.
  - Return values are unchanged.

### 13. Lifecycle
- **Init:**
  - `nodes/intake.ts`: call `initDebugTrace()` after `initResponseLog()` and log the trace path.
  - `continue/singleton-rehydration.ts`: same call, with `continuation: true`; it appends to the existing trace.
- **Crash:**
  - `run.ts` `handleRunCrash()` writes a `run:crash` record.
  - `utils/crash-handlers.ts` writes a `crash` record and the summary (synchronously, best-effort) on uncaughtException, unhandledRejection, SIGINT and SIGTERM.
- **Finalize:** `nodes/finalize.ts` calls `writeDebugSummary()` in its own try/catch after the run diagnosis. This does not touch the guaranteed state writes (Rule 18).

## Risks / considerations
- **Size:** roughly tens of MB per run with de-duplication. `DEBUG_TRACE_MAX_FIELD_CHARS` caps each field; the complete agent outputs are still in `full-responses/`. Debug mode is meant for diagnosis runs, not always-on use.
- **Synchronous file writes in debug mode only.** This is a deliberate exception to Rule 24, for crash safety and exact ordering, and matches `run-ledger.ts` and the logger. Capturing the caller's stack per command is negligible next to LLM latency.
- **Sensitive content is captured on purpose:** prompts, requirements, source code and tool output. Credentials are redacted, but treat the folder as confidential before sharing it with an external AI.
- **Behaviour change by design:** run.log in normal runs gets quieter (16 `debug()` sites).
- **New convention:** never import `child_process` directly. Any future direct import would be invisible to the trace; this is documented in AI_Context.
- **`_awaitHandler`** is a typed `BaseCallbackHandlerInput` option, and a test asserts it. If LangChain ever drops it, LLM records are still written, but ordering and phase/branch context may degrade.
- **Server mode with concurrent runs:** process-level crash records go to the most recently initialised run's trace.
