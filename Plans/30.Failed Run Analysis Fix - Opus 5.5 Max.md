# Plan 30: Stuck PR #2 loop (root cause, fixes) and token efficiency

The partial `claudeopus5` run got stuck because one feature branch was wrongly treated as the scaffold branch. That branch was dispatched before the branches it depended on, it halted every other branch when it failed, and it was then re-run from scratch, unchanged, in every bug-fix round, where its pushes were rejected and QA fed back false bugs. Fixing that loop, plus making prompt caching actually cover the conversation history, removes most of the 20M-input-token spend without changing what the agents deliver.

## 0. How to use this plan

**Approved decisions:**
- Halt policy: skip only the branches that depend on a failed branch.
- Blocked branches: resume from the remote branch instead of restarting.
- Branch wall cap: scale it with the number of assignments, and defer the remaining work when it still runs out.
- After approval, save a copy as `Plans/30.Stuck PR Loop & Token Efficiency - Opus 5.5 Max.md`.

### 1.2 Primary causal chain (why it got stuck)

1. **Scaffold misclassification.**
   - `isScaffoldAssignment()` treats any `taskType: 'chore'` as scaffold, and `isScaffoldBranch()` uses `.some()` (`dispatcher.ts` L158–173).
   - ASSIGN-026 (an asset audit, typed `chore`) made us-027 a "scaffold" branch.
   - Two unit tests encode exactly this behaviour: `tests/scaffold-classification.test.ts` L61–63 and L95–98.
2. **Story-ID canonicalisation overrides the Team Leader's explicit branches.**
   - `canonicalBranchName()` (L104–121) sends every assignment of a story to the first branch seen for that story.
   - That pulled ASSIGN-004/005 (US-001) and ASSIGN-027 (US-035) into the scaffold branch.
   - Later it pulled the bug-fix assignments for US-027…034 onto the blocked branch (6 → 7 → 13 assignments).
3. **Barrier injection creates cycles.**
   - ASSIGN-027 matched the bootstrap keyword `\bwiring\b` (L199–222).
   - `injectBootstrapDependencies` made every feature assignment depend on ASSIGN-027, which itself depends on all of them.
   - Result: a 23-assignment cycle, and `topoSort` gave up on ordering (L82–87).
4. **Branches are dispatched without honouring cross-branch dependencies.** When any assignment of a branch shows up in a layer, all of the branch's assignments run (L437–445). us-027's work ran against `throw new Error('not implemented')` stubs.
5. **Strict halt amplifies one failure into a total stall** (L621–644). The halt also reuses the `prCreationFailed` flag, which produces the misleading log at L785–793.
6. **The loop repeats unchanged.** ASSIGN-026 never merges, so steps 1–5 recur every round. `detectUnrecoverable()` (`acceptance-gate.ts` L429–489) never fires:
   - Its zero-progress check counts *unmerged* file changes (`dispatchRounds[1] = {fileChanges:2, prs:0}`).
   - It ignores the `blocked` PR status.
   - It only counts repeated attempts for `ACCEPT-`/`GATE-` bugs.
   - Only `MAX_BUGFIX_ITERATIONS` would have ended the run (at least one more ~35-minute round).

### 1.3 Why PR #2 could not merge, even on its own merits

- **Dependencies were unmet** (see 1.2 step 4).
- **The invocation ceiling discards finished work.** It is checked after the fact, counts raw input including cache reads (`token-tracker.ts` L370–376), and throws even when the agent produced valid output (`agent-invoke.ts` L159–170). A full junior invocation (43 turns × ~15k tokens ≈ 650k) always exceeds 600k: Plan 27-C doubled the turn budgets but kept Plan 24's ceiling. 23 invocations crossed it.
- **A 15-minute wall cap for a 6–13-assignment branch.** Dev work gets cut, while the PR, review, escalation and strong fixer still run.
- **Stale merge evidence.** `decideMerge` uses the gate report from before review and fix commits (`orchestrator.ts` L663–670).
- **In rounds 2–3, work was destroyed and pushes failed silently:**
  - `createBranchWorktree` deletes the local branch and recreates it from base (`worktree.ts` L75, L106).
  - `commitWorktree` ignores the push result and logs "Branch pushed" anyway (`commit.ts` L37, L46).
  - Reviewers reviewed local code that never reached PR #2.
  - Approving PR #2 would have merged the stale round-1 head.

### 1.4 Why QA's 63 bugs per round were all false

- **Test runner:** `detectNodeFramework` defaults to Jest and adds `--ci --json --outputFile … --coverage` to `ng test` (`test-runner.ts` L440–473). Round 1 also ran before `npm install` (exit 127). Result: 0 tests, `QA-runner-error`, 35 `QA-story-untested-*` and 25 `AC-*` bugs.
- **Salvage directory as a product root:** `PRUNE_DIRS` lacks `.worktrees-failed` (`fs-walk.ts` L13–16), so the salvaged worktree became a 2nd root. That caused `PRODUCT-ARTIFACTS-root` and `GATE-node-test-.worktrees-failed-…`.
- **Smoke test serves the wrong directory:** it serves `dist/`, but Angular 17 outputs `dist/claudeopus5/browser/` (`product-verify.ts` L218–230, L719–746). `pollForReady` needs a 2xx response, so the error says "server did not become ready within 60000ms".
- **Wrong argument:** `checkTestSufficiency` is handed assignment IDs as `completedStoryIds` (`qa.ts` L274). It also runs the per-story checks even when the runner failed.
- **Real problems never reached triage:** PR #2's actual review findings were absent, and traceability labels every blocked PR "Merge conflicts or review blocked". The Team Leader therefore invented conflicts and file paths (`src/app/services/high-score.service.ts`).

**Goal:**
- Only the scaffold branch *name* makes a branch the scaffold.
- The Team Leader's explicit branches are honoured.
- Barrier injection never creates cycles.
- Branches dispatch in cross-branch dependency order.
- A failed branch blocks only the branches that depend on it.

- `src/agents/developers/dispatcher.ts` (817 LOC; split it)

- `src/agents/team-leader/team-leader.prompt.ts`
- `src/config.ts`, `.env.example`
- `src/utils/event-bus.ts`
- tests

**Steps:**

1. Move the pure planning code into `dispatch-plan.ts` and update imports (no shim, Rule 29). That covers `topoSort`, `canonicalBranchName`, `SCAFFOLD_BRANCH_RE`, the `is*`/`inject*` helpers, `findOverlappingBranches`, `primaryTaskType` and `collectReviewers`. Bring `dispatcher.ts` under 600 LOC.
2. Scaffold classification by branch name only:
   - `isScaffoldAssignment(a)` becomes `SCAFFOLD_BRANCH_RE.test(a.branchName ?? '')`.
   - `isScaffoldBranch(branch)` becomes `SCAFFOLD_BRANCH_RE.test(branch)`.
   - Remove the `taskType === 'chore'` check and the `.some()` fallback.
   - Invert the 2 tests that encoded the old behaviour.
3. Canonical branch selection:
   - An explicit `branchName` wins (prefix, sanitize and `assertValidRef` as today).
   - Without one: use the branch of the first assignment of the same story that is not on the scaffold, or else `featureBranch()`.
   - Never move a non-scaffold assignment into the scaffold, or a scaffold assignment out of it.
   - When one story spans several branches, emit a `story-branch-split` warning.
4. Barriers without cycles:
   - Add a `wouldCreateCycle` reachability check; skip injected edges that would close a cycle and record them in `plan.skippedEdges`.
   - Scaffold assignments drop dependencies on non-scaffold work, with a warning.
   - "Bootstrap" now requires the existing entry-module or keyword match **and** no transitive dependency on non-scaffold work. Otherwise the assignment's kind is `finalizer`: no edges are injected and it simply runs last. ASSIGN-027 becomes a finalizer.
5. `topoSort`: replace the "one parallel batch" fallback with deterministic SCC (Tarjan) cycle breaking. Log an ERROR naming the removed edges, and record them in `plan.brokenEdges`.
6. Branch DAG dispatch:
   - `buildDispatchPlan()` returns `{ branches: Map<name, {kind, assignments (intra-branch topo order), dependsOnBranches}>, branchOrder, warnings, skippedEdges, brokenEdges }`.
   - A branch starts only when all of its `dependsOnBranches` have merged or are pre-satisfied.
   - Branch-level cycles: break them deterministically and warn.
   - Keep overlap serialisation inside a layer.
   - This replaces "gather ALL the branch's assignments as soon as one of them appears in a layer".
7. Halt policy:
   - Add `'dependents'` to the `DISPATCH_HALT_POLICY` enum and make it the default (approved).
   - A non-merged branch skips its transitive dependents for this round (their assignments stay pending), emits `dispatch:skipped-dependents`, and writes a transcript entry.

   - A failed scaffold still blocks everything, so Plan 27-B's savings remain.
8. Replace the `prCreationFailed` overload with `stopReason: 'pr-creation-failed' | 'halt-policy' | 'provider-<kind>' | 'budget' | null`, and make the final logs report the real reason.
9. Delete the private `syncWorkspaceToBranch` (L292–297).
   - After a scaffold or bootstrap merge, call the one in `conductor/workspace-sync.ts`. If it returns `ok === false`, log an ERROR and add a transcript entry.
   - Never check out a feature branch in the main checkout. The Plan 26 A5 fallback (under `off`) passes `origin/<scaffold>` as the base ref instead.
10. Observability: one `dispatch:plan` event plus a ledger entry (`kind: 'dispatch-plan'`). It records each branch's kind and the reason (e.g. "finalizer: depends on 23 feature assignments"), its assignments, its dependencies, skipped and broken edges, and the dispatch order.
11. `validateAssignmentPlan` gets new findings:
    - `dependency-cycle` (critical → Team Leader repair prompt that shows the cycle)
    - `scaffold-depends-on-feature` (major)
    - `story-branch-split` (info)
    - `finalizer-on-shared-branch` (major)

### 30-02: Honest branch lifecycle and resumable re-dispatch

**Goal:**
- A PR claims only the assignments that actually ran.
- No valid output is ever discarded.
- The merge decision uses fresh evidence.
- Blocked or deferred branches resume from their remote head.
- Push failures are never silent.

**Files:**
- `src/conductor/pr/orchestrator.ts` (758 LOC; move the per-assignment loop into NEW `pr/assignment-runner.ts` and the merge evidence into NEW `pr/merge-decision.ts`)
- `pr/worktree.ts` (`createBranchWorktree` only)
- `pr/commit.ts`, `pr/agent-invoke.ts`, `pr/pr-github.ts`, `pr/strong-fixer.ts`
- `src/utils/github-local.ts`
- `src/conductor/assignment-policy.ts`
- `src/conductor/nodes/development.ts`
- `schemas/pr.schema.ts`
- `src/utils/traceability.ts`
- `continue/state-collector.ts`, `continue/git-reconciliation.ts`
- config, tests

**Steps:**

1. **Executed vs deferred assignments.**
   - The assignment loop records `executed` (the agent ran, whatever the outcome) and `deferred` (never started because of the branch budget).
   - `PullRequest.assignmentIds` lists only the executed ones; the result also carries `deferredAssignmentIds`.
   - Deferred work stays pending automatically. This fixes ASSIGN-027's phantom completion.
2. **Wall cap (approved: scale + defer).**
   - Effective cap = `MAX_BRANCH_WALL_MS + MAX_BRANCH_WALL_PER_ASSIGNMENT_MS × (n − 1)`. The new env var defaults to 360000.
   - If the cap still runs out before every assignment has run:
     - commit and push the partial work;
     - skip gates, PR and review;
     - return the new PR status **`'deferred'`**.
   - The dispatcher treats `deferred` as not merged, so its dependents are skipped this round; the next round resumes the branch (step 5).
   - The schema change cascades (Rule 5). Update every PR-status consumer: dispatcher summaries and halt logic, `development.ts`, `qa.ts` L412/425, `traceability.ts` L376–381/422/490, `run-snapshot.ts` L295, `continue/state-collector.ts` L444–451, `continue/git-reconciliation.ts` L498, and the finalize/report renderers.
3. **Never discard valid output** (`agent-invoke.ts` L159–170 and L245–254).
   - When the ceiling is exceeded after a generation that parsed successfully, return that output with `budgetCapped: true` and don't respawn.
   - Throw only when there is no valid output.
   - The strong fixer then still runs its gates and final review.
   - Ledger outcome: `ok-budget-capped`.
4. **Fresh merge evidence.**
   - Remember the HEAD sha from the last gate run. If HEAD has moved before `decideMerge`, re-run the quality and integrity gates on the worktree.
   - Pass the *actual* review-iteration count, and fix the escalation log message to match.
5. **Resume from remote (approved).**
   - If `origin/<branch>` exists, run `git worktree add <dir> -B <branch> origin/<branch>`, then `integrateBase()` (merge in the latest base) before any dev work. Delete the `reset --hard` to base (L95–104).
   - Detect already-executed assignments from commit subjects, using a single formatter/parser pair in `commit.ts` that matches `… work from <dev> on <ASSIGN-ID> (durable commit)`.
   - Run only the not-yet-executed and new bug-fix assignments, then gates, then reuse the PR (`createOrReusePR`), then review.
6. **Push verification.**
   - `commitWorktree` checks the result of `gitPush`. On non-fast-forward it fetches, rebases onto `origin/<branch>` (merge as fallback) and retries once.
   - On a final failure it returns `{pushed:false, error}`, logs an ERROR and emits `branch:push-failed`.
   - Log "Branch pushed" only on success.
   - The orchestrator's final push (L393–399) must succeed before PR creation; otherwise the branch fails with reason `push-rejected` and gets no review or merge.
7. **Merge guard.**
   - Before `mergePr`, check that `pulls.get().head.sha` equals the local `HEAD`; otherwise block with "remote head stale".
   - Extend the local GitHub stand-in's `pulls.get` to return `head: {ref, sha}`.
8. **Completion evidence.**
   - Resolve `moduleIds` to paths through `repoContract.modules`, passing the contract in `PRWorkflowInput`. If an ID can't be resolved, report the module check as "n/a" rather than 0/N.
   - Wire `completedIdsWithEvidence()` and `incompleteBugs()` into `developmentNode` (the intended Sub-Plan 06 §6 behaviour).
9. **Continue-run.**
   - `blocked`, `open` and `deferred` branches that have a remote head count as resumable: keep the remote branch and the PR (skip the `CONTINUE_CLOSE_STALE_PRS` close), and delete only the local branch.
10. **Honest logs and ledger.**
