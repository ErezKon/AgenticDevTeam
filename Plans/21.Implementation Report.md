## 2. Changes by sub-plan

### Sub-plan B — OpenAI Responses-API JSON mode (E2)

`src/agents/_shared/llm-provider.ts`
- Removed the `modelKwargs: { response_format: … }` branch. JSON mode is now applied as a **call option**: `model.withConfig({ response_format: { type: 'json_object' } })`.
- LangChain then routes it through `_getResponseFormat()`, emitting `response_format` on Chat Completions and `text: { format: … }` on the Responses API. One code path, no model-name sniffing to keep in sync with upstream.

`src/conductor/nodes.ts` (`qaNode` catch block)
- The QA-Lead failure log now carries the model name, HTTP status, and the provider's error body on one line, so a recurrence is diagnosable without a package dive. The existing `QA-LEAD-FAILED` synthesis is unchanged.

**Verified against the real package** (not just the mock) in `tests/openai-responses-json-mode.test.ts`: an unauthenticated `ChatOpenAI('gpt-5.3-codex')` built by `createChatModel` yields `invocationParams().text.format.type === 'json_object'` and **no** top-level `response_format`; `gpt-4o` still yields `response_format` and no `text`.

### Sub-plan A — Anthropic streaming corruption (E1) + dead config

**A1** `llm-provider.ts`: kept `streaming: true` on `ChatAnthropic` — Anthropic's HTTP endpoint times out after ~10 minutes on non-streaming requests, which kills long agent runs. The E1 streaming residue is neutralised by A2's sanitiser instead of by disabling streaming. Token accounting for streaming responses is handled by D's two-tier lookup (`usage_metadata` fallback).

**A2** `src/agents/_shared/history-compactor.ts`: new exported `sanitizeStreamingContentBlocks(messages)`.
- Drops any content block whose `type` ends in `_delta`, and any `tool_use` / `server_tool_use` block with a missing or empty `id`.
- Leaves `tool_calls` untouched — the provider adapter re-materialises the blocks from it.
- Operates on a copy; returns the **same array reference** when nothing changed (zero-cost on clean histories).

Wired into the `history-compaction` middleware in `agent-factory.ts`, **before** `compactHistory`, gated by the new `SANITIZE_STREAM_BLOCKS` flag (default `true`). The middleware is now registered when *either* `HISTORY_COMPACTION_ENABLED` or `SANITIZE_STREAM_BLOCKS` is on, so disabling compaction no longer disables the sanitiser.

**A3** `agent-factory.ts`: `topP` / `topK` from `AgentConfig` are now forwarded to `createChatModel()`. `topP` is also passed through to `ChatOpenAI` (`topK` is Anthropic-only).

**A4** `src/agents/developers/dispatcher.ts`: the completion log distinguishes merged from skipped PRs (`N PRs (M merged, K skipped)` — the old `16 PRs` line actively misled), and a round where **every** branch produced zero commits and zero merged PRs now logs `ERROR` and pushes a transcript entry.

**A5** `llm-provider.ts`: adaptive-only models (`claude-opus-4-7+`, `claude-opus-4-8+`, `claude-opus-5+`, `claude-fable-5+`, `claude-mythos-*`) are detected by regex matching `ADAPTIVE_ONLY_MODEL_PREFIXES` in `@langchain/anthropic@1.5.4`. For these models, `temperature`, `topK`, and `topP` are **omitted entirely** from the `ChatAnthropic` constructor object — the SDK's `validateInvocationParamCompatibility()` reads the **class properties** (not the constructor args), so simply not passing a field is insufficient when the class has a non-`undefined` default. All other constructor args are passed normally. A debug log records the detection.

### Sub-plan D — Universal token accounting (E4)

`src/utils/token-usage-extractor.ts` now owns the shared normalisation helpers:
- `normaliseUsage(usage)` — handles `promptTokens`/`prompt_tokens`/`input_tokens` and their output/total counterparts.
- `sumUsageMetadata(messages)` — sums `usage_metadata` across messages.
- `extractTokenUsageFromMessages` was refactored onto these, so the per-call and per-invocation paths cannot drift.

`src/utils/token-callback.ts` `handleLLMEnd` is now a two-tier lookup:
1. `llmOutput.tokenUsage ?? token_usage ?? usage ?? estimatedTokenUsage`
2. fallback: `generations[…].message.usage_metadata`

Tier 1 wins when present, so providers that populate both are never double-counted. The "no token usage" line was promoted from `DEBUG` to a **WARN, deduped per agent+model** (`TokenUsageCallbackHandler.resetUsageWarnings()` clears it for tests/run start).

**Deviation from the plan (deliberate).** The plan said to add `input_token_details.cache_read|cache_creation` on top of `input_tokens`. Checking the installed `@langchain/anthropic@1.5.4` (`buildUsageMetadata`, `dist/utils/message_outputs.js:179-192`) shows `usage_metadata.input_tokens` **already** includes both, so adding them again would over-count by the full cache size. Instead `normaliseUsage` adds `cache_creation_input_tokens` / `cache_read_input_tokens` only to **raw** Anthropic usage (`llmOutput.usage`), where they genuinely are separate — detected by the absence of `total_tokens` / `input_token_details`. Both cases are covered by tests.

### Sub-plan C — Runaway detection (E3)

- `developmentNode` now returns `dispatchRounds: [{ fileChanges, prs, completed }]`, with `prs` counting **merged** PRs only. A zero round is logged at `ERROR`.
- `DispatchRound.prs` is documented as merged-only in `acceptance-gate.ts`; `PR-SKIPPED-*` placeholders (`prNumber: 0`, `status: 'closed'`) are explicitly not progress.
- `detectUnrecoverable()` is now called at the **top of `bugfixTriageNode`**. Under `RUN_FAIL_POLICY=halt` the node short-circuits, sets `state.unrecoverable`, and dispatches nothing; under other policies it flags the state and continues so downstream gates report truthfully.
- The `phase:end` event for development now reports the merged-PR count, not the raw record count.

### Sub-plan E — Bug-fix triage story-id integrity (E5)

1. **Schema** — `BugSchema` gains optional `storyId`. Purely additive; traced consumers (`test-sufficiency.ts`, `assignment-policy.ts`, `nodes.ts` triage, `traceability.ts`) need no changes.
2. **Source** — `sufficiencyViolationsToBugs()` populates `storyId` from `v.storyId`, so the real story is structured data rather than prose in `suspectedArea`.
3. **Prompt** — `bugfixTriageNode` adds a `Valid Story IDs` context section and an explicit instruction never to put a bug id in `storyId`.
4. **Validator (load-bearing)** — new `sanitizeAssignmentStoryIds(assignments, userStories, bugs)` in `assignment-policy.ts`, applied after `namespaceBugfixAssignments`. Resolution ladder: known story → keep; bug with a known `storyId` → remap; `/^QA-.*-(US-\d+)$/` with an existing story → remap; otherwise drop (`storyId` becomes `''`) and log once. `additionalStoryIds` is filtered identically and de-duplicated against the primary.
5. `pr-workflow.ts:748` is kept as the last-resort tripwire.

Dropping to `''` is safe: the branch story-id collector at `pr-workflow.ts:742` already does `.filter(Boolean)`, so the story section is omitted entirely rather than claiming criteria that do not exist.

### Sub-plan F — Diagnosable git failures (E6)

`src/utils/git-exec.ts`
- New exported `describeGitFailure(err, args, timeoutMs)`. When `stderr` and `message` are both empty (the SIGTERM-on-timeout case that produced the literal `"Error:"`), it synthesises a message from `signal` / `status` / `code`, and every error is prefixed with the failing subcommand: `Error: [git fetch] git exited via SIGTERM (timeout after 30000ms)`.
- `gitExec` / `gitExecVerbose` take an optional `timeoutMs`. The default is chosen per subcommand: 30 s locally, `GIT_NETWORK_TIMEOUT_MS` (default 120 s) for `fetch`/`push`/`pull`/`clone`/`ls-remote`.
- `gitExecVerbose` can no longer return an empty `stderr`.

`src/conductor/workspace-sync.ts`
- New exported `fetchWithRetry(gitRoot, branch, attempts = 3)` using `gitExecVerbose` with exponential backoff (1 s, 2 s).
- `syncWorkspaceToBranch` uses it for the network fetch and logs the exit code plus stderr on failure.

## 5. Notes and deviations

| Item | Decision |
|------|----------|
| Streaming kept on ChatAnthropic (A1) | Anthropic's HTTP endpoint times out after ~10 minutes on non-streaming requests, killing long agent runs. Streaming is guarded by A2's sanitiser. Token accounting is handled by D's two-tier lookup. |
| Adaptive-only model detection (A5) | The regex must stay in sync with `ADAPTIVE_ONLY_MODEL_PREFIXES` in `@langchain/anthropic`'s `params.ts`. A comment marks the coupling. Mismatch is noisy (the SDK throws at call time), not silent. |
| Anthropic cache tokens (sub-plan D) | The plan's instruction would have double-counted them for `usage_metadata`. Cache tokens are added only to **raw** `llmOutput.usage`; `usage_metadata` already folds them in. Verified against the installed package source. |
| `sanitizeAssignmentStoryIds` dropping to `''` | `Assignment.storyId` is a required string, so an unresolvable id becomes `''` rather than being deleted. Safe because `pr-workflow.ts:742` filters falsy ids. |
| Sanitiser registration | The plan wired the sanitiser inside the `history-compaction` middleware, which was previously registered only when `HISTORY_COMPACTION_ENABLED`. The middleware is now registered when either flag is on, so the two features are genuinely independent. |
| `acceptance-gate.ts` merged-PR counting | The two existing PR counts in that file already filtered on `status === 'merged'`; the real defect was that `dispatchRounds` was never populated. Only a doc-comment change was needed there. |
| E1 and the dependency bump | `@langchain/anthropic@1.5.4` already fixes the adapter side. A2 is kept because the failure mode is silent, total, and billable, and because the upstream fix does not cover checkpoint-resume of an already-corrupt history. |
