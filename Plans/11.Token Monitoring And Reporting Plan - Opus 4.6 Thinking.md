# Token Monitoring Feature for AgenticDevTeam

Add per-agent token usage tracking across each run, with totals and an HTML report saved to the run's output folder.

---

## Summary

Every agent invocation (architect, PM, DBA, team-leader, codebase-analyzer, developers, reviewers, QA agents, devops) calls `agent.invoke()` which returns LangChain messages with `usage_metadata` (`input_tokens`, `output_tokens`, `total_tokens`). We will:

1. Extract token usage from every agent invocation
2. Accumulate it in the LangGraph project state via an append reducer
3. In the finalize node, generate a self-contained HTML report with charts and tables
4. Save both the raw JSON data and the HTML report to the run's output folder

---

## Implementation Steps

### Step 1: Create Token Usage Schema

**New file: `src/agents/_shared/schemas/token-usage.schema.ts`**

Define a Zod schema for a single token usage record:
```ts
{
  agentId: string,     // e.g. "architect", "junior-react"
  phase: PhaseName,    // pipeline phase when tokens were used
  inputTokens: number, // prompt tokens
  outputTokens: number,// completion tokens
  totalTokens: number, // sum
  model: string,       // model name used
  timestamp: string,   // ISO timestamp
}
```

Export as `TokenUsageRecord` type and `TokenUsageRecordSchema`.

### Step 2: Export from Schema Barrel

**Modify: `src/agents/_shared/schemas/index.ts`**

Add `export * from './token-usage.schema';`

### Step 3: Add tokenUsage to Project State

**Modify: `src/conductor/state.ts`**

Add a new `tokenUsage` field:
```ts
tokenUsage: Annotation<TokenUsageRecord[]>({
    reducer: appendReducer,
    default: () => [],
}),
```

This uses the existing `appendReducer` so all agent results accumulate.

### Step 4: Create Token Extraction Utility

**New file: `src/utils/token-tracker.ts`**

Create a utility function `extractTokenUsage(result, agentId, phase)` that:
- Iterates through `result.messages`
- Filters for messages with `usage_metadata` (AI messages)
- Sums up `input_tokens`, `output_tokens`, `total_tokens` across all AI messages in the result (a react agent can make multiple LLM round-trips for tool calls)
- Returns a `TokenUsageRecord` object

Also export a helper to get the model name from config based on agent ID.

### Step 5: Modify `invokeAgent()` in `nodes.ts`

**Modify: `src/conductor/nodes.ts`**

Change `invokeAgent()` to also return token usage data alongside the parsed JSON:
```ts
async function invokeAgent(agent, userMessage, threadSuffix, agentId, phase): Promise<{ output: any; tokenUsage: TokenUsageRecord }>
```

The function will:
1. Call `agent.invoke()` as before
2. Before parsing the last message, iterate all messages to extract token usage
3. Return both the parsed output and the token usage record

Update every node function (architectNode, productManagerNode, dbaNode, etc.) to:
- Destructure `{ output, tokenUsage }` from `invokeAgent()`
- Include `tokenUsage: [tokenUsage]` in the returned state update

### Step 6: Modify PR Workflow for Token Tracking

**Modify: `src/conductor/pr-workflow.ts`**

- Update `invokeDevAgent()` and `invokeReviewerAgent()` to extract token usage from their results
- Add `tokenUsage: TokenUsageRecord[]` to `PRWorkflowResult`
- Collect token usage from all dev agent and reviewer agent invocations
- Return token usage in the result

**Modify: `src/agents/developers/dispatcher.ts`**

- Add `tokenUsage: TokenUsageRecord[]` to `DispatchResult`
- Propagate token usage from PR workflow results

**Modify: `src/conductor/nodes.ts` (developmentNode)**

- Include accumulated tokenUsage from dispatch result in the state update

### Step 7: Add Model Pricing Configuration

**Modify: `src/config.ts`**

Add a `MODEL_PRICING` map with per-model cost per 1K tokens (input and output):
```ts
export const MODEL_PRICING: Record<string, { inputPer1k: number; outputPer1k: number }> = {
    'gpt-oss-120b': { inputPer1k: 0.006, outputPer1k: 0.012 },
    'llama-3-3-70b-instruct': { inputPer1k: 0.003, outputPer1k: 0.006 },
    // ... etc for all configured models
};
```

Pricing values are configurable defaults; users can adjust via environment variables or config.

### Step 8: Create HTML Report Generator

**New file: `src/utils/token-report.ts`**

Create `generateTokenReport(records: TokenUsageRecord[], outputPath: string)` that:

1. **Aggregates data**:
   - Total tokens across all agents
   - Tokens per agent (summed across invocations)
   - Tokens per phase
   - Input vs output token breakdown
   - **Estimated cost** per agent and total, using MODEL_PRICING

2. **Generates fully self-contained HTML** with:
   - **Summary header**: total tokens, total agents, estimated total cost, run timestamp
   - **Pie chart**: Token distribution by agent (Chart.js inline-bundled)
   - **Bar chart**: Input vs Output tokens per agent (stacked)
   - **Bar chart**: Tokens by pipeline phase
   - **Cost table**: Estimated cost per agent (input cost + output cost)
   - **Detailed table**: Every invocation with agent, phase, input/output/total tokens, model, cost, timestamp
   - Clean, modern CSS styling (dark theme matching the terminal aesthetic)

3. **Saves files**:
   - `{outputPath}/token-usage.json` - raw data
   - `{outputPath}/token-usage-report.html` - the visual report

Chart.js is **inline-bundled** (minified JS embedded directly in the HTML) so the report works fully offline with no external dependencies.

### Step 9: Integrate Report Generation in Finalize Node

**Modify: `src/conductor/nodes.ts` (finalizeNode)**

- Import and call `generateTokenReport(state.tokenUsage, state.outputPath)`
- Add token summary to the finalize log output and run summary artifact
- Add a transcript message with total token count

## Risks/Considerations

- **Token data availability**: If the LLM provider doesn't return `usage_metadata` (some OpenAI-compatible APIs omit it), the records will have 0 values. The code handles this gracefully with fallback to 0.
- **No new npm dependencies**: Chart.js is bundled inline in the HTML. No new packages needed.
- **Backward compatibility**: The `tokenUsage` state field defaults to `[]`, so existing runs/tests are unaffected.
- **Performance**: Token extraction is lightweight (just iterating message arrays). No measurable impact on agent execution time.
- **Model name mapping**: We'll create a helper to map agent IDs to their configured model names using the existing config constants.
